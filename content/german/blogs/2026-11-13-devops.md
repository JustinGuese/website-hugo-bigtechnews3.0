<h2 id="die-http2-race-condition-des-apache-http-server-ist-ein-patch-jetzt-fall">Die HTTP/2-Race Condition des Apache HTTP Server ist ein Patch-jetzt-Fall</h2>

CVE-2026-119618 ist eine kritische Remote-Codeausführungsschwachstelle in `mod_http2`, dem HTTP/2-Modul des Apache HTTP Server. Der Bug ist eine Race Condition in der Funktion `assign_headers()`, die zu Heap-Korruption führt, und erfolgreiche Ausnutzung erlaubt einem nicht authentifizierten Remote-Angreifer, beliebigen Code auszuführen. Noch ist kein Exploit öffentlich, aber Wiz-Telemetrie zeigt, dass 64 Prozent der Cloud-Umgebungen verwundbare Ressourcen haben und 51 Prozent öffentlich exponierte Instanzen - das ist viel Angriffsfläche, die darauf wartet, dass jemand einen PoC schreibt.

Betroffen sind Apache HTTP Server 2.4.55 bis 2.4.70, gepatcht in 2.4.71 und später, sowie mod_h2 2.0.8 bis 2.0.42, gepatcht in 2.0.42+. Wer nicht sofort upgraden kann, für den ist das Deaktivieren der HTTP/2-Unterstützung die Abhilfe. Für alle, die eine Standard-Apache-Installation hinter einem Load Balancer betreiben, der TLS terminiert, gilt: Prüfen, ob HTTP/2 überhaupt ausgehandelt wird, bevor man annimmt, sicher zu sein - das Modul kann trotzdem geladen und verwundbar sein, selbst wenn man glaubt, nur HTTP/1.1 zu bedienen.

Google hat eine [Referenzarchitektur für den Betrieb von CodeMender](https://ecommerce-api.datafortress.cloud/r/brieftechnews/WYdf4pzlrkgwNqBBwFY7Sw/djF8d2VifDIwMjYtMTEtMTMtZGV2b3BzfGNvZGVtZW5kZXItaMO2cnQtYXVmLXp1LW1lbGRlbi11bmQtYmVnaW5udC16dS1iZWhlYmVuLWluLWlocmVuLXB1bGwtcmVxdWVzdHN8fGh0dHBzOi8vY2xvdWQuZ29vZ2xlLmNvbS9ibG9nL3Byb2R1Y3RzL2lkZW50aXR5LXNlY3VyaXR5L2hvdy10by1ydW4tY29kZW1lbmRlci1pbi15b3VyLXB1bGwtcmVxdWVzdHMvP3V0bV9zb3VyY2U9YnJpZWYtdGVjaC1uZXdzLmNvbQ) veröffentlicht, seinen autonomen Code-Sicherheitsagenten, direkt in Git-Pull-Requests über Cloud Run. Der Workflow sind Slash-Befehle in der PR-Zeitleiste: `/verify` führt eine Exploit-Simulation in einer Sandbox aus, um zu bestätigen, ob ein Befund tatsächlich ausnutzbar ist, und `/fix` generiert einen vorgeschlagenen Code-Diff mit einem Entwurf-Pull-Request. Befunde kommen mit Konfidenzwerten zurück, und Verifikationsergebnisse können Schweregradbewertungen ändern - das Tool kann also einen False Positive herabstufen, bevor ein Mensch ihn überhaupt sieht.

Das adressiert ein reales operatives Problem: Die durchschnittliche Entwickler-Fix-Zeit für Softwarefehler ist von 59 Tagen vor einem Jahrzehnt auf über 170 Tage im Jahr 2025 gestiegen. Das Sicherheitsteam meldet, der Entwickler ignoriert, das Ticket verrottet. CodeMinders Modell kollabiert diese Schleife in einen einzigen PR-Kommentar. Die Architektur verwendet kurzlebige OIDC-Tokens statt gespeicherter Schlüssel, sodass kein neues Geheimnis zum Rotieren hinzukommt.

Heroku-Postgres-Standard-Tiers bieten keine logische Replikation oder WAL-Zugriff, was die Migration großer Datenbanken zu einem mehrstündigen Ausfallereignis macht. [PlanetScale hat einen Open-Source-Heroku-Migrator gebaut](https://ecommerce-api.datafortress.cloud/r/brieftechnews/u9rlDK3FekrDac5JnO6tyw/djF8d2VifDIwMjYtMTEtMTMtZGV2b3BzfHBsYW5ldHNjYWxlLW1pZ3JpZXJ0LXRlcmFieXRlcy12b24taGVyb2t1LW9obmUtbG9naXNjaGUtcmVwbGlrYXRpb258fGh0dHBzOi8vcGxhbmV0c2NhbGUuY29tL2Jsb2cvbWlncmF0ZS1mcm9tLWhlcm9rdS10by1wbGFuZXRzY2FsZT91dG1fc291cmNlPWJyaWVmLXRlY2gtbmV3cy5jb20), der die Einschränkung komplett umgeht. Version 2.0 teilt den Prozess in Datenübertragungs- und Index-Rebuild-Phasen, was die Kopiergeschwindigkeit um etwa das Fünffache erhöht.

Für Teams, die auf Herokus Standard-Plänen festsitzen, ist das der Unterschied zwischen einem geplanten Wartungsfenster und einer Live-Migration. Das Tool ist Open Source, sodass es gegen jedes Ziel ausgeführt werden kann, nicht nur gegen PlanetScale.

<p class="small mb-4"><a href="https://ecommerce-api.datafortress.cloud/r/brieftechnews/8BeSh7GNexQGLDbe98_GJw/djF8d2VifDIwMjYtMTEtMTMtZGV2b3BzfHRlbnNvcmZvbGQtZWluZS16aWctYmFzaWVydGUtbGxtLWluZmVyZW56LWVuZ2luZXx8aHR0cHM6Ly9naXRodWIuY29tL2FzaGhhcnQvVGVuc29yRm9sZD91dG1fc291cmNlPWJyaWVmLXRlY2gtbmV3cy5jb20" target="_blank" rel="noopener noreferrer">Source: github.com ↗</a></p>

[TensorFold](https://ecommerce-api.datafortress.cloud/r/brieftechnews/8BeSh7GNexQGLDbe98_GJw/djF8d2VifDIwMjYtMTEtMTMtZGV2b3BzfHRlbnNvcmZvbGQtZWluZS16aWctYmFzaWVydGUtbGxtLWluZmVyZW56LWVuZ2luZXx8aHR0cHM6Ly9naXRodWIuY29tL2FzaGhhcnQvVGVuc29yRm9sZD91dG1fc291cmNlPWJyaWVmLXRlY2gtbmV3cy5jb20) ist eine in Zig geschriebene LLM-Serving-Engine, die auf Apple Silicon und NVIDIA-GPUs läuft. Sie liest Checkpoints und führt Metal- oder CUDA-Kernel direkt aus, ohne Python- oder MLX-Installation. Installation über Homebrew mit `brew install ashhart/tensorfold/tensorfold`, und der empfohlene Ausgangspunkt ist Qwen3.5-2B, ein kleiner 4-Bit-Checkpoint, der auf Metal und GB10 getestet wurde.

Das Interessante ist das integrierte Agent Traffic Control (ATC)-System zur Koordination von Coding-Agenten, die am Projekt selbst arbeiten - Befehle zum Prüfen, Beanspruchen und Pulsen von Issues. Es ist eine Dogfooding-Geschichte für KI-gestützte Entwicklung, und eine Zig-Binary, die LLMs ohne Python-Runtime bedient, ist für Edge-Deployments wirklich schlank.

Das CNCF Technical Oversight Committee hat [Open Cluster Management als Incubating-Projekt angenommen](https://ecommerce-api.datafortress.cloud/r/brieftechnews/Yy6lZKvrXmgxPyOG9j_aTg/djF8d2VifDIwMjYtMTEtMTMtZGV2b3BzfG9wZW4tY2x1c3Rlci1tYW5hZ2VtZW50LXN0ZWlndC16dW0tY25jZi1pbmN1YmF0aW5nLXByb2pla3QtYXVmfHxodHRwczovL3d3dy5jbmNmLmlvL2Jsb2cvMjAyNi8xMS8xMC9vcGVuLWNsdXN0ZXItbWFuYWdlbWVudC1vY20tYmVjb21lcy1hLWNuY2YtaW5jdWJhdGluZy1wcm9qZWN0Lz91dG1fc291cmNlPWJyaWVmLXRlY2gtbmV3cy5jb20) und es damit von der Sandbox, der es im November 2021 beigetreten war, hochgestuft. Das asynchrone Pull-Modell erhält Cluster-Autonomie, ohne Zugangsdaten zu zentralisieren, was für Edge-Deployments mit intermittierender Konnektivität wichtig ist.

Ursprünglich von IBM und Red Hat entwickelt, erreichte es im Juni 2025 Version 1.0 und hat seitdem Updates bis 1.4 im Oktober 2026 geliefert. Zu den wichtigsten Funktionen gehören CEL-basierte Cluster-Auswahl, ein Argo-CD-Pull-Model-Add-on und ein pluggables Add-on-Framework. eBay nutzt es Berichten zufolge mit Argo CD über mehr als 190 Cluster - eine solide reale Referenz für Multi-Cluster-Verwaltung im großen Maßstab.

[GitHubs Secret Scanning erkennt nun Geheimnisse in Actions-Workflow-Logs](https://ecommerce-api.datafortress.cloud/r/brieftechnews/4Z89grmq-1KjVop2gYZWbA/djF8d2VifDIwMjYtMTEtMTMtZGV2b3BzfGdpdGh1Yi1zZWNyZXQtc2Nhbm5pbmctw7xiZXJ3YWNodC1udW4tYWN0aW9ucy13b3JrZmxvdy1sb2dzfHxodHRwczovL2dpdGh1Yi5ibG9nL2NoYW5nZWxvZy8yMDI2LTExLTA5LXNlY3JldC1zY2FubmluZy1kZXRlY3RzLXNlY3JldHMtaW4tZ2l0aHViLWFjdGlvbnMtd29ya2Zsb3ctbG9ncy8_dXRtX3NvdXJjZT1icmllZi10ZWNoLW5ld3MuY29t), verfügbar in öffentlicher Vorschau für Unternehmen auf GitHub Enterprise Cloud mit Secret Protection oder GitHub Advanced Security. Wenn ein Workflow-Lauf abgeschlossen ist, scannt GitHub die Logs auf Provider-Muster und erhebt Repository-Alerts mit Links zum betreffenden Log. Die Funktion ist standardmäßig deaktiviert und muss von Enterprise-Ownern in den Advanced-Security-Richtlinien aktiviert werden.

Die Einschränkungen sind wichtig: Nur Workflow-Läufe, die nach der Aktivierung der Funktion abgeschlossen wurden, werden gescannt, und generische Muster, benutzerdefinierte Muster, KI-erkannte Geheimnisse und bereits maskierte Geheimnisse werden nicht erkannt. Wenn ein Geheimnis letzten Monat in einem Log geleakt ist, wird das nicht rückwirkend gefunden.

[Istio 1.32.0 ist draußen](https://ecommerce-api.datafortress.cloud/r/brieftechnews/5o65Bt9pLbxMSTdcdeAqRg/djF8d2VifDIwMjYtMTEtMTMtZGV2b3BzfGlzdGlvLTEzMjAtYnJpbmd0LWdhdGV3YXktYXBpLWF1dG9yaXNpZXJ1bmctdW5kLWVhc3Qtd2VzdC12ZXJlaW5oZWl0bGljaHVuZ3x8aHR0cHM6Ly9pc3Rpby5pby9sYXRlc3QvbmV3cy9yZWxlYXNlcy8xLjMyLngvYW5ub3VuY2luZy0xLjMyLz91dG1fc291cmNlPWJyaWVmLXRlY2gtbmV3cy5jb20), verwaltet von Release-Managern von Microsoft, Tetrate und Solo.io. Zu den Sicherheitsfunktionen gehört die Möglichkeit, JWT-Regeln in RequestAuthentication als REQUIRED zu markieren. Für alle, die gemischte Ambient- und Sidecar-Meshes betreiben, entfernt das einheitliche East-West-Gateway einen echten operativen Kopfschmerz.
