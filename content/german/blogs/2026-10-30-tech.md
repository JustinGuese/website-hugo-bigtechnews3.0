David Cramer beschrieb, wie Sentry das Refactoring von Code - konkret [die Portierung von Diensten nach Rust mittels Opus 5.5 über den Agenten Junior](https://ecommerce-api.datafortress.cloud/r/brieftechnews/fhX_qZTGJJHll3qLhV-9TQ/djF8d2VifDIwMjYtMTAtMzAtdGVjaHxhZ2VudC1hcmNoaXRla3R1ci1lZ3Jlc3MtcHJveHlzLXVuZC1wci1pdGVyYXRpb25lbi1zdGF0dC1zdGFycmVyLWd1YXJkcmFpbHN8fGh0dHBzOi8vY3JhLm1yL2EtbGl0dGxlLWRldGVybWluaXNtP3V0bV9zb3VyY2U9YnJpZWYtdGVjaC1uZXdzLmNvbQ) - automatisiert hat. Die zentrale Erkenntnis: Fest verdrahtete System-Prompts verschlechtern die Problemlösungskompetenz von LLMs. Zu rigides Prompting zur Erzwingung von Determinismus führt zu fehleranfälligen Ausführungspfaden.

Statt die interne Denkschleife des Agenten einzuengen, führt Sentry diesen frei in einer isolierten microVM-Sandbox aus und steuert das Verhalten von außen:

```
[Agent Core] <---> [MitM Egress Proxy] <---> [Network / APIs]
                         │
                   (Deny Action)
                         │
                         ▼
        [Automated PR Review Comment Feedback]
```

1. **Egress-Interzeption:** Ein zwischengeschalteter Egress-Proxy überwacht ausgehende Befehle und blockiert unautorisierte Aktionen direkt auf Netzwerkebene.
2. **Review-Feedbackschleifen:** Statt spezieller Syntaxkonstrukte erhält der Agent standardisiertes Pull-Request-Feedback und Compiler-Fehler als natürliche Korrektur-Prompts.
