Das Unternehmen hat [AWS Continuum for code vulnerabilities allgemein verfügbar gemacht](https://ecommerce-api.datafortress.cloud/r/brieftechnews/X6eygRmyyRXtbn1n7Ot4aQ/djF8d2VifDIwMjYtMTAtMjYtZGV2b3BzfHx8aHR0cHM6Ly9hd3MuYW1hem9uLmNvbS9hYm91dC1hd3Mvd2hhdHMtbmV3LzIwMjYvMTAvYXdzLWNvbnRpbnV1bS1mb3ItY29kZS12dWxuZXJhYmlsaXRpZXMtaXMtbm93LWdlbmVyYWxseS1hdmFpbGFibGUvP3V0bV9zb3VyY2U9YnJpZWYtdGVjaC1uZXdzLmNvbQ). Der Dienst kombiniert Umgebungstopologiedaten aus GuardDuty und Security Hub mit einer automatisierten Sandbox, die reale Exploits testet, bevor Entwickler alarmiert werden. Öffnet die Sandbox eine Shell, erstellt Continuum einen Pull Request mit dem entsprechenden Patch.

Die Veröffentlichung erfolgt an einem Tag, an dem die Branche eine solche Pipeline dringend benötigt. Eine kritische Heap-Corruption-Schwachstelle namens Broccoli2Shell trifft den kanonischen C-Brotli-Decoder und setzt Node.js, Bun sowie Envoy-Proxys dem Risiko einer unauthentifizierten Remote-Codeausführung aus. Gleichzeitig fordert Railway Kunden aus 100.000 Workspaces auf, sämtliche API-Tokens zu rotieren, nachdem Angreifer eingedrungen sind, um LLM-Schlüssel zu entwenden.

Wer Infrastruktur betreibt, muss heute Edge-Runtimes patchen, Kernel-Versionen gegen sechs neu offengelegte Zero-Day-Lücken prüfen und Zugangsdaten rotieren.

> AWS Continuum kann automatisch Pull Requests mit verifizierten Patches eröffnen und reduziert den Zeitaufwand für das Triage von False Positives auf wenige Minuten.

Statt lediglich vor einer verwundbaren Abhängigkeit zu warnen, startet Continuum eine isolierte Sandbox-Umgebung, die die Servicekonfiguration nachbildet, und führt eine automatisierte Exploit-Verifikationsroutine aus. Wird die Verwundbarkeit in dieser Topologie bestätigt, berechnet die Engine den Explosionsradius, generiert einen Fix und reicht einen automatisierten Pull Request ein. Plattform-Teams können den Dienst in einem beobachtenden Learn-Modus betreiben, der manuelle Freigaben erfordert, bevor der autonome Enforce-Modus Fixes direkt in Staging- oder Produktions-Pipelines einspeist.

Da Brotli ubiquitär in HTTP-Netzwerk-Stacks eingebettet ist, erben nachgelagerte Runtimes wie Node.js, Bun und Envoy Proxy die Schwachstelle direkt. Eine erfolgreiche Ausnutzung kann zu Speicherenthüllungen, Daemon-Abstürzen oder unauthentifizierter Remote-Codeausführung führen. Telemetriedaten von Wiz zeigen, dass 91 % der Enterprise-Cloud-Umgebungen verwundbare Ressourcen enthalten, deren Code gegen ungepatchte Brotli-Decoder gelinkt ist. Jeder Edge-Proxy und Microservice, der komprimierte HTTP-Payloads annimmt, benötigt umgehend einen Rebuild und Patch der zugrundeliegenden Runtime.

Google löst diesen Konflikt durch eine [Anthropic-verwaltete Deployment-Option direkt in Google Cloud](https://ecommerce-api.datafortress.cloud/r/brieftechnews/DyjK0x0taqJ3rru5G-5rEA/djF8d2VifDIwMjYtMTAtMjYtZGV2b3BzfGdvb2dsZS1jbG91ZC1mw7xocnQtYW50aHJvcGljLXZlcndhbHRldGUtY2xhdWRlLWRlcGxveW1lbnRzLWbDvHItc29mb3J0aWdlLWZlYXR1cmUtdmVyZsO8Z2JhcmtlaXQtZWlufHxodHRwczovL2Nsb3VkLmdvb2dsZS5jb20vYmxvZy9wcm9kdWN0cy9haS1tYWNoaW5lLWxlYXJuaW5nL2V4cGFuZGluZy1jbGF1ZGUtYXZhaWxhYmlsaXR5LW9uLWdvb2dsZS1jbG91ZC8_dXRtX3NvdXJjZT1icmllZi10ZWNoLW5ld3MuY29t).

Die Anthropic-verwaltete Stufe bietet vollständige Feature-Parität ab Tag null mit Anthropics eigener Plattform - inklusive Claude Managed Agents, Ausführung benutzerdefinierter Tools und nativer Code-Interpretation - auf Modellen wie Claude Fable 5.1, Sonnet 5.5, Haiku 5.5 und Opus 5.5. Die Abrechnung erfolgt über bestehende Google-Cloud-Commitments, und der Zugriff wird über Standard-IAM von Google Cloud geregelt, wobei Anthropic als externer Auftragsverarbeiter fungiert. Teams, die isolierte Netzwerkperimeter wie VPC Service Controls oder Customer-Managed Encryption Keys (CMEK) vorschreiben, verbleiben bei der Google-verwalteten Modelloption.

<h2 id="shard-groups-in-neki-halten-postgres-joins-lokal-ohne-cross-cluster-fan-out"><a href="https://ecommerce-api.datafortress.cloud/r/brieftechnews/RPRvjfidAp-hY6cgkXH1Og/djF8d2VifDIwMjYtMTAtMjYtZGV2b3BzfHNoYXJkLWdyb3Vwcy1pbi1uZWtpLWhhbHRlbi1wb3N0Z3Jlcy1qb2lucy1sb2thbC1vaG5lLWNyb3NzLWNsdXN0ZXItZmFuLW91dHx8aHR0cHM6Ly9wbGFuZXRzY2FsZS5jb20vYmxvZy9zaGFyZC1ncm91cHMtdGhlLXVuaXQtb2YtY28tbG9jYXRpb24_dXRtX3NvdXJjZT1icmllZi10ZWNoLW5ld3MuY29t" target="_blank" rel="noopener noreferrer">Shard Groups in Neki halten Postgres-Joins lokal ohne Cross-Cluster-Fan-out</a></h2>

<p class="small mb-4"><a href="https://ecommerce-api.datafortress.cloud/r/brieftechnews/RPRvjfidAp-hY6cgkXH1Og/djF8d2VifDIwMjYtMTAtMjYtZGV2b3BzfHNoYXJkLWdyb3Vwcy1pbi1uZWtpLWhhbHRlbi1wb3N0Z3Jlcy1qb2lucy1sb2thbC1vaG5lLWNyb3NzLWNsdXN0ZXItZmFuLW91dHx8aHR0cHM6Ly9wbGFuZXRzY2FsZS5jb20vYmxvZy9zaGFyZC1ncm91cHMtdGhlLXVuaXQtb2YtY28tbG9jYXRpb24_dXRtX3NvdXJjZT1icmllZi10ZWNoLW5ld3MuY29t" target="_blank" rel="noopener noreferrer">Source: planetscale.com ↗</a></p>

Die Verteilung einer relationalen Datenbank über horizontale Knoten bricht typischerweise Fremdschlüssel-Constraints und macht aus simplen Tabellen-Joins verteilte Map-Reduce-Abfragen mit hoher Latenz. In einer technischen Analyse beschreibt PlanetScale, wie [Shard Groups die Datenlokalität in Neki lösen](https://ecommerce-api.datafortress.cloud/r/brieftechnews/RPRvjfidAp-hY6cgkXH1Og/djF8d2VifDIwMjYtMTAtMjYtZGV2b3BzfHNoYXJkLWdyb3Vwcy1pbi1uZWtpLWhhbHRlbi1wb3N0Z3Jlcy1qb2lucy1sb2thbC1vaG5lLWNyb3NzLWNsdXN0ZXItZmFuLW91dHx8aHR0cHM6Ly9wbGFuZXRzY2FsZS5jb20vYmxvZy9zaGFyZC1ncm91cHMtdGhlLXVuaXQtb2YtY28tbG9jYXRpb24_dXRtX3NvdXJjZT1icmllZi10ZWNoLW5ld3MuY29t), seiner Architektur für Sharded Postgres.

Statt jede Tabelle unabhängig zu hashen, konfigurieren Datenbankarchitekten gemeinsame Shard Groups anhand einer Tenant-ID. Über einen 64-Bit-`xxhash`-Schlüsselindex auf `customer_id` wird garantiert, dass übergeordnete Tabellen (wie `accounts`) und untergeordnete Tabellen (wie `invoices` oder `orders`) mit demselben Schlüssel auf denselben physischen Postgres-Knoten geschrieben werden. Abfragen bleiben lokal, Transaktionen behalten ihre Single-Node-ACID-Garantien, und sekundäre Indizes decken nicht-geshardete Pfade ab, ohne dass komplexe knotenübergreifende Broadcast-Abfragen erforderlich sind.

<h2 id="cloudflare-origin-range-requests-machen-manuelles-cache-slicing-überflüssig"><a href="https://ecommerce-api.datafortress.cloud/r/brieftechnews/XnCCnRE6ftnN-UFVG8_TBQ/djF8d2VifDIwMjYtMTAtMjYtZGV2b3BzfGNsb3VkZmxhcmUtb3JpZ2luLXJhbmdlLXJlcXVlc3RzLW1hY2hlbi1tYW51ZWxsZXMtY2FjaGUtc2xpY2luZy3DvGJlcmZsw7xzc2lnfHxodHRwczovL2Jsb2cuY2xvdWRmbGFyZS5jb20vb3JpZ2luLXJhbmdlLXJlcXVlc3RzLz91dG1fc291cmNlPWJyaWVmLXRlY2gtbmV3cy5jb20" target="_blank" rel="noopener noreferrer">Cloudflare Origin Range Requests machen manuelles Cache-Slicing überflüssig</a></h2>

<p class="small mb-4"><a href="https://ecommerce-api.datafortress.cloud/r/brieftechnews/XnCCnRE6ftnN-UFVG8_TBQ/djF8d2VifDIwMjYtMTAtMjYtZGV2b3BzfGNsb3VkZmxhcmUtb3JpZ2luLXJhbmdlLXJlcXVlc3RzLW1hY2hlbi1tYW51ZWxsZXMtY2FjaGUtc2xpY2luZy3DvGJlcmZsw7xzc2lnfHxodHRwczovL2Jsb2cuY2xvdWRmbGFyZS5jb20vb3JpZ2luLXJhbmdlLXJlcXVlc3RzLz91dG1fc291cmNlPWJyaWVmLXRlY2gtbmV3cy5jb20" target="_blank" rel="noopener noreferrer">Source: blog.cloudflare.com ↗</a></p>

Das Streaming großer Mediendateien oder der Download massiver Disk-Images aus Object-Stores führt häufig zu ineffizientem Datenverkehr. Standard-Edge-Caches fordern oft ganze 128-MiB-Segmente vom Origin an, selbst wenn ein Client nur einen 8-KiB-Chunk abfragt, um in einem Video vorzuspulen. Cloudflare hat die Range-Request-Architektur in seinem Rust-basierten Pingora-Proxy neu implementiert und [Origin Range Requests als Self-Service-Feature](https://ecommerce-api.datafortress.cloud/r/brieftechnews/XnCCnRE6ftnN-UFVG8_TBQ/djF8d2VifDIwMjYtMTAtMjYtZGV2b3BzfGNsb3VkZmxhcmUtb3JpZ2luLXJhbmdlLXJlcXVlc3RzLW1hY2hlbi1tYW51ZWxsZXMtY2FjaGUtc2xpY2luZy3DvGJlcmZsw7xzc2lnfHxodHRwczovL2Jsb2cuY2xvdWRmbGFyZS5jb20vb3JpZ2luLXJhbmdlLXJlcXVlc3RzLz91dG1fc291cmNlPWJyaWVmLXRlY2gtbmV3cy5jb20) in den Cache Rules für alle Tarifstufen freigeschaltet.

Die Engine koordiniert parallele Byte-Range-Requests direkt zwischen aktivem Edge-Speicher, lokalen Cache-Slices und laufenden Upstream-Abrufen. In Produktions-Benchmarks mit dem Objektspeicher Cloudflare R2 reduzierte die neue Routing-Logik die p99 Time-to-First-Byte (TTFB) um rund 50 % und senkte den Tiered-Cache-Backhaul um 6 %. Teams, die große statische Binärdateien ausliefern, können willkürliche Slice-Regeln entfernen, ohne Cache-Thrashing im Edge-Speicher zu riskieren.

<h2 id="kubernetes-control-planes-skalieren-wo-die-bruchstellen-liegen"><a href="https://ecommerce-api.datafortress.cloud/r/brieftechnews/Sf85wxcQGZBrVln_lwz9VQ/djF8d2VifDIwMjYtMTAtMjYtZGV2b3BzfGt1YmVybmV0ZXMtY29udHJvbC1wbGFuZXMtc2thbGllcmVuLXdvLWRpZS1icnVjaHN0ZWxsZW4tbGllZ2VufHxodHRwczovL3RoZW5ld3N0YWNrLmlvL3NjYWxpbmcta3ViZXJuZXRlcy1jb250cm9sLXBsYW5lcy8_dXRtX3NvdXJjZT1icmllZi10ZWNoLW5ld3MuY29t" target="_blank" rel="noopener noreferrer">Kubernetes-Control-Planes skalieren: Wo die Bruchstellen liegen</a></h2>

<p class="small mb-4"><a href="https://ecommerce-api.datafortress.cloud/r/brieftechnews/Sf85wxcQGZBrVln_lwz9VQ/djF8d2VifDIwMjYtMTAtMjYtZGV2b3BzfGt1YmVybmV0ZXMtY29udHJvbC1wbGFuZXMtc2thbGllcmVuLXdvLWRpZS1icnVjaHN0ZWxsZW4tbGllZ2VufHxodHRwczovL3RoZW5ld3N0YWNrLmlvL3NjYWxpbmcta3ViZXJuZXRlcy1jb250cm9sLXBsYW5lcy8_dXRtX3NvdXJjZT1icmllZi10ZWNoLW5ld3MuY29t" target="_blank" rel="noopener noreferrer">Source: thenewstack.io ↗</a></p>

Große Cluster scheitern selten an der oft zitierten Upstream-Marke von 5.000 Knoten aufgrund eines einzelnen Limits. Ein Architekturbericht von The New Stack analysiert [drei typische Engpässe bei der Skalierung der Control Plane](https://ecommerce-api.datafortress.cloud/r/brieftechnews/Sf85wxcQGZBrVln_lwz9VQ/djF8d2VifDIwMjYtMTAtMjYtZGV2b3BzfGt1YmVybmV0ZXMtY29udHJvbC1wbGFuZXMtc2thbGllcmVuLXdvLWRpZS1icnVjaHN0ZWxsZW4tbGllZ2VufHxodHRwczovL3RoZW5ld3N0YWNrLmlvL3NjYWxpbmcta3ViZXJuZXRlcy1jb250cm9sLXBsYW5lcy8_dXRtX3NvdXJjZT1icmllZi10ZWNoLW5ld3MuY29t) in Enterprise-Umgebungen: Node-bound, Churn-bound und Operator-bloated Cluster.

Bei 100.000 Knoten erreicht der Cluster-Traffic rund 10.000 Schreibvorgänge pro Sekunde, wobei einfache Node-Lease-Erneuerungen fast 70 % der gesamten Schreib-QPS ausmachen. Umgekehrt scheitern Cluster, die von benutzerdefinierten Agent-Plattformen dominiert werden, nicht an der Knotendichte, sondern an hochfrequentem Objekt-Churn, der den Serialisierungspfad von etcd überlastet. Plattform-Teams versuchen oft fälschlicherweise, die Last durch das Hochskalieren von `kube-apiserver`-Replikaten abzufangen. Da jedoch jede Instanz einen eigenen lokalen Watch-Cache zur Replikation des Cluster-Status vorhält, erschöpfen zusätzliche API-Server lediglich den etcd-Compaction-Durchsatz und belegen übermäßig viel Control-Plane-Speicher.

Das Release enthält zudem `percentile_disc()`, `percentile_cont()` und Subsampling auf SQL-Ebene.

Entwickler, die PaaS-Flexibilität ohne Cloud-Lock-in suchen, setzen verstärkt auf [Coolify, eine quelloffene Self-Hosting-Alternative](https://ecommerce-api.datafortress.cloud/r/brieftechnews/I7YKLk9Wko0WLvq-KN5PXA/djF8d2VifDIwMjYtMTAtMjYtZGV2b3BzfHF1ZXN0ZGItMTAxLWNvb2xpZnktc2VsZi1ob3N0aW5nLXVuZC1raS1pbmZyYXN0cnVrdHVyLXRvb2xzfHxodHRwczovL2dpdGh1Yi5jb20vY29vbGxhYnNpby9jb29saWZ5P3V0bV9zb3VyY2U9YnJpZWYtdGVjaC1uZXdzLmNvbQ) zu Heroku und Vercel. Im Bereich KI-Betrieb stellte Grafana Labs ein Framework vor, das [SRE-basierte SLOs und Error-Budgets für LLM-Agents](https://ecommerce-api.datafortress.cloud/r/brieftechnews/J47w9sMLs0VoM2ioMTKp_A/djF8d2VifDIwMjYtMTAtMjYtZGV2b3BzfHF1ZXN0ZGItMTAxLWNvb2xpZnktc2VsZi1ob3N0aW5nLXVuZC1raS1pbmZyYXN0cnVrdHVyLXRvb2xzfHxodHRwczovL3d3dy5pbmZvcS5jb20vbmV3cy8yMDI2LzEwL2dyYWZhbmEtc2xvLWFpLWFnZW50Lz91dG1fc291cmNlPWJyaWVmLXRlY2gtbmV3cy5jb20) empfiehlt.
