Google will die Kontext-Aufblähung deines Agenten beseitigen. Die Gemini API hat jetzt [Tool Retrieval](https://ecommerce-api.datafortress.cloud/r/brieftechnews/73Cr0m5o5pv9bZyWEoVIeA/djF8d2VifDIwMjYtMTEtMjAtYWl8fHxodHRwczovL2Jsb2cuZ29vZ2xlL2lubm92YXRpb24tYW5kLWFpL3RlY2hub2xvZ3kvZGV2ZWxvcGVycy10b29scy9nZW1pbmktYXBpLXRvb2wtcmV0cmlldmFsLz91dG1fc291cmNlPWJyaWVmLXRlY2gtbmV3cy5jb20), eine Preview-Funktion in der Interactions API, die verhindert, dass das Modell jedes Tool-Schema im Voraus lädt. Stattdessen sieht es Namen und Beschreibungen und zieht dann das vollständige JSON-Schema bei Bedarf innerhalb derselben Anfrage. Das bedeutet, dass man hunderte Tools registrieren kann, ohne den Prompt aufzublähen oder die Latenzsteuer für Schemas zu zahlen, die das Modell nie anfasst. Die Suche findet serverseitig statt, es gibt also keinen Index, den man aufbauen oder pflegen müsste. Für alle, die Agent-Schleifen betreiben, die pro Runde ein Dutzend Funktionsdefinitionen durchreichen, ist das der Unterschied zwischen einem 2k-Token-Kontext und einem 20k-Token-Kontext.

Das Modell entscheidet basierend auf der Benutzereingabe, was geladen wird - das ist für die meisten Workflows die richtige Entscheidung. Aber es ist eine Preview, also sollte man erwarten, dass die Retrieval-Logik vorerst eine Blackbox ist. Der Gewinn ist real: Agenten, die an einer 50-Tool-API-Oberfläche erstickt wären, können jetzt ohne einen eigenen Router vor Gemini skalieren.
