Die neue [Gemini Decisions API](https://ecommerce-api.datafortress.cloud/r/brieftechnews/ang_y3swBaInpE7ggHQuoQ/djF8d2VifDIwMjYtMTEtMTItYWl8Z2VtaW5pLWRlY2lzaW9ucy1hcGktZW50c2NoZWlkdW5nZW4tb2huZS1nZW5lcmllcnVuZ3x8aHR0cHM6Ly9ibG9nLmdvb2dsZS9pbm5vdmF0aW9uLWFuZC1haS90ZWNobm9sb2d5L2RldmVsb3BlcnMtdG9vbHMvZ2VtaW5pLWRlY2lzaW9ucy1hcGkvP3V0bV9zb3VyY2U9YnJpZWYtdGVjaC1uZXdzLmNvbQ) von Google ist eine andere Art von Endpunkt. Statt Tokens zu generieren, bewertet sie bis zu 1.000 unabhängige Fragen gegen einen einzigen multimodalen Input - Text, Bilder, Audio, Video, PDFs, bis zu 256K Tokens - in einem Vorwärtsdurchlauf. Sie liefert Wahrscheinlichkeiten und Konfidenzwerte mit 150 - 250 ms Ende-zu-Ende-Latenz und berechnet null Ausgabe-Tokens.

Das dahinterliegende Modell, gemini-decision-1, verarbeitet Ja/Nein-Fragen, Multiple Choice und Rubrik-Bewertung. Google behauptet, es sei fast 5x günstiger als Gemini 3.5 Flash-Lite mit der Interactions API. Für Entwickler ersetzt dies eine ganze Klasse von Token-für-Token-Generierung durch einen kalibrierten Klassifikator: Tool-Auswahl, Policy-Prüfungen, Modell-Routing, Content-Moderation. Wer diese als Prompt-und-Parse-Schleifen gebaut hat, für den ist das das Ende dieser Schleifen.

Der Kompromiss ist, dass es eine geschlossene Menge ist. Man bekommt Wahrscheinlichkeiten, keine Prosa. Wenn die Pipeline neben der Entscheidung auch eine Erklärung braucht, ist weiterhin ein generatives Modell nötig - aber für die Entscheidung selbst ist das dramatisch günstiger und schneller.

[OpenRouter hat gemessen](https://ecommerce-api.datafortress.cloud/r/brieftechnews/bQkrpPznHr92Sp8uWvNXbQ/djF8d2VifDIwMjYtMTEtMTItYWl8bWNwLXZzLWNsaS12cy1za2lsbHMtZGllLXZlcnN0ZWNrdGVuLWtvc3Rlbi12b24tdG9vbC1kZWZpbml0aW9uZW58fGh0dHBzOi8vb3BlbnJvdXRlci5haS9ibG9nL2luc2lnaHRzL21jcC12cy1jbGktdnMtc2tpbGxzLz91dG1fc291cmNlPWJyaWVmLXRlY2gtbmV3cy5jb20), was es in Tokens kostet, Agenten Tools zu geben - und die Zahlen sind brutal. Bei einer GitHub-Aufgabe mit Claude Sonnet 5.5 nutzte die CLI 1.421 Eingabe-Tokens, das Skill 3.315 und der GitHub-MCP-Server 59.417 - dessen 46 Standard-Tools fügten 19.436 Tokens pro Anfrage hinzu. Ein einziges Tool-Ergebnis, das GitHub-Release-Objekt, kostete etwa 20.400 Tokens.

Der Mechanismus ist einfach: Tool-Definitionen werden bei jeder Anfrage als Eingabe-Tokens abgerechnet. MCP-Server mit Dutzenden von Tools blähen den Kontext bei jedem einzelnen Aufruf auf, ob der Agent sie nutzt oder nicht. Der Tool Search Server von OpenRouter senkt die anfänglichen Tool-Kosten auf unter 600 Tokens und halbiert die Gesamtkosten bei Sonnet 5.5. Wer Agenten in Produktion betreibt, für den ist das der Unterschied zwischen einer tragfähigen Stückkosten und einer Rechnung, die die Marge auffrisst. Die Lösung ist Lazy Tool Loading - Definitionen erst dann laden, wenn der Agent sie tatsächlich braucht.
