<p class="small mb-4"><a href="https://ecommerce-api.datafortress.cloud/r/brieftechnews/N3mG6CnaQUV7Z6UnMx0G5A/djF8d2VifDIwMjYtMTEtMTMtdGVjaHxzbG9wLXdhbmRlcnQtaW0tc3RhY2stbmFjaC1vYmVufHxodHRwczovL2dhYmVvcmxhbnNraS5naXRodWIuaW8vcG9zdHMvc2xvcC1tb3Zlcy11cC8_dXRtX3NvdXJjZT1icmllZi10ZWNoLW5ld3MuY29t" target="_blank" rel="noopener noreferrer">Source: gabeorlanski.github.io ↗</a></p>

KI-Agenten schreiben saubereren Code, aber das Chaos migriert. [Neue Benchmarks von Gabe Orlanski](https://ecommerce-api.datafortress.cloud/r/brieftechnews/N3mG6CnaQUV7Z6UnMx0G5A/djF8d2VifDIwMjYtMTEtMTMtdGVjaHxzbG9wLXdhbmRlcnQtaW0tc3RhY2stbmFjaC1vYmVufHxodHRwczovL2dhYmVvcmxhbnNraS5naXRodWIuaW8vcG9zdHMvc2xvcC1tb3Zlcy11cC8_dXRtX3NvdXJjZT1icmllZi10ZWNoLW5ld3MuY29t) zeigen, dass Spitzen-Agenten jetzt deutlich mehr SlopCodeBench-Checkpoints lösen und dabei weniger Slop auf Codeebene produzieren. Das Problem: Slop ist im Stack nach oben in Designentscheidungen gewandert. Die neuen LibraryDesignBench- und LibraryUseBench-Benchmarks zeigen, dass Agenten keine Weitsicht darüber haben, wie ihr Code verwendet wird - sie zeigen schlechtes Abstraktionsdesign und ignorieren die Wiederverwendung von Bibliothekscode völlig.

Die Lösungsraten bei SlopCodeBench steigen weiter auf allen drei Teststufen (strict, isolated und core). Aber die Benchmarks legen eine andere Fehlerart offen: Ein Agent, der korrekten Code mit schrecklicher Architektur schreibt, ist argumentativ schlechter als einer, der schlampigen Code schreibt, den man reviewen kann. Das Abstraktionsproblem ist das schwerer zu lösende, weil es Urteilsvermögen über zukünftige Anwendungsfälle erfordert, nicht nur Syntax.
