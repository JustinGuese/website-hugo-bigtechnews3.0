The Danish multinational energy operator automated its policy pipelines using Network to Code's Nautobot platform, dropping rule generation, validation, and sign-off times down to roughly 10 minutes. Enterprise network teams know the drill: an engineer requests port 443 open between two internal subnets, security needs a week to assess zone transit, a CAB meets next Tuesday, and the rule lands 14 days later. [Ørsted automated its firewall pipeline](https://ecommerce-api.datafortress.cloud/r/brieftechnews/KxNF9v7lkky6CL44Ns1CTA/djF8d2VifDIwMjYtMTAtMTMtaXR8w7hyc3RlZC1idWlsZHMtYXV0b21hdGVkLWNvbXBsaWFuY2UtaW50by1uZXR3b3JrLXBpcGVsaW5lc3x8aHR0cHM6Ly93d3cubmV0d29ya3dvcmxkLmNvbS9hcnRpY2xlLzQyMjkwNDgvb3JzdGVkLWJ1aWxkcy1jb21wbGlhbmNlLWludG8tYXV0b21hdGlvbi1zcGVlZHMtZmlyZXdhbGwtY2hhbmdlcy5odG1sP3V0bV9zb3VyY2U9YnJpZWYtdGVjaC1uZXdzLmNvbQ) using the open-source Nautobot network automation platform, collapsing those multi-week change windows down to around 10 minutes.

Nautobot functions as both a Network Source of Truth (NSoT) and an application platform. Rather than having engineers submit manual ticket changes across distributed firewalls, Ørsted built custom validators and internal apps on top of Nautobot to model its internal network zones. When a change request comes in, Nautobot evaluates the proposed traffic flow against predefined compliance policies and permission rules. If it passes validation, the system provisions the rule directly, creating an immutable audit trail without manual ticket tennis.

Treating network policy as software verification is the only way hybrid infrastructure scales. When network definitions live in an extensible NSoT that supports programmatic hooks, security switches from a reactive ticketing queue to a runtime integration test.

Physical operational tech took a direct hit when [attackers compromised Danfoss refrigeration controllers](https://ecommerce-api.datafortress.cloud/r/brieftechnews/ucBo0rHtxmhxb38OAwU3jA/djF8d2VifDIwMjYtMTAtMTMtaXR8c3VwZXJtYXJrZXQtY2hpbGxlci1jb250cm9sbGVycy1hdHRhY2tlZC1hY3Jvc3MtZnJhbmNlfHxodHRwczovL3d3dy5ibGVlcGluZ2NvbXB1dGVyLmNvbS9uZXdzL3NlY3VyaXR5L2N5YmVyYXR0YWNrLXNodXRzLWRvd24tcmVmcmlnZXJhdG9ycy1hdC1mcmVuY2gtc3VwZXJtYXJrZXRzLz91dG1fc291cmNlPWJyaWVmLXRlY2gtbmV3cy5jb20) running outdated control-software versions in French supermarkets. The attack struck between 250 and 350 stores - including locations belonging to Intermarché, Carrefour Market, and Leclerc - triggering automated defrost cycles that raised cold-storage temperatures and spoiled thousands of euros in food inventory.

The incident highlights the operational vulnerabilities of OT hardware. Building management systems and industrial chillers rarely receive prompt firmware patches, and controller management interfaces are routinely exposed to shared contractor networks or reachable via misconfigured VPNs. The attackers did not brick the hardware; they simply leveraged legitimate controller commands to turn heaters on and compressors off during operational hours.

If your organization runs facilities hardware, HVAC, or smart PDUs alongside IT infrastructure, isolate their controllers onto out-of-band management VLANs with strict ingress filtering. A controller does not need to suffer remote code execution to cause an outage if an attacker can manipulate operational setpoints using default or outdated management protocols.

Mark Seemann weighed in on [releasing AI-generated software without human inspection](https://ecommerce-api.datafortress.cloud/r/brieftechnews/nC2mx1p_0pScAXdsYTd2DQ/djF8d2VifDIwMjYtMTAtMTMtaXR8Y2FuLXRlc3Qtc3VpdGVzLXJlcGxhY2UtaHVtYW4tcmV2aWV3cy1mb3ItYWktZ2VuZXJhdGVkLWNvZGV8fGh0dHBzOi8vYmxvZy5wbG9laC5kay8yMDI2LzEwLzEyL3JlbGVhc2luZy1haS1nZW5lcmF0ZWQtc29mdHdhcmUvP3V0bV9zb3VyY2U9YnJpZWYtdGVjaC1uZXdzLmNvbQ), picking up a debate sparked by Robert C. Martin ("Uncle Bob"), who claimed he no longer reads LLM-produced code line-by-line, relying on test suites instead. Seemann argues that traditional code review has always offered a false sense of security; shifting toward automated verification, regression tests, and falsifiable predictions provides a more objective safety net than tired engineers skimming pull requests.

However, relying entirely on green tests to validate synthetic code introduces liability and maintenance risks. Standard test suites only assert the behaviors a developer thought to define. LLMs frequently produce subtle edge-case bugs, non-idiomatic abstractions, and resource leaks that satisfy isolated unit assertions while introducing architectural rot. Treating code as an untrusted black-box artifact requires property-based testing, fuzzing, and runtime mutation tests, not just standard unit checks.
