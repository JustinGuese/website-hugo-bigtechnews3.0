Nvidia's dedicated inference silicon is no longer a paper launch. The Groq 3 LPX accelerator is in full production as an extension of the [Vera Rubin data center platform](https://ecommerce-api.datafortress.cloud/r/brieftechnews/ndqiwNovBs3DxUBwCqS6xg/djF8d2VifDIwMjYtMDgtMjUtaXR8fHxodHRwczovL3NpbGljb25hbmdsZS5jb20vMjAyNi8wOC8yNC9udmlkaWFzLWRlZGljYXRlZC1pbmZlcmVuY2UtYWNjZWxlcmF0b3ItZ3JvcS0zLWxweC1lbnRlcnMtZnVsbC1wcm9kdWN0aW9uLXRvLXN1cGVyY2hhcmdlLWFpLWFnZW50cy8_dXRtX3NvdXJjZT1icmllZi10ZWNoLW5ld3MuY29t), with Nebius Group as the first committed cloud customer. A full rack-scale deployment bolts up to 256 LP30 accelerators onto Vera Rubin GPUs over high-bandwidth interconnects, and the design splits the work cleanly: Vera Rubin GPUs handle context processing, the LPX boxes handle token generation. That separation is what makes it interesting for agentic AI, where the bottleneck is decode latency on long, multistep chains rather than raw pretraining throughput. If you are sizing inference fleets for agent workloads, this is the architecture to model against.

Kai Wähner's [post on when not to use stream processing](https://ecommerce-api.datafortress.cloud/r/brieftechnews/Qx8AAKr5xR4f6amlLaXPtw/djF8d2VifDIwMjYtMDgtMjUtaXR8c3RvcC1yZWFjaGluZy1mb3Ita2Fma2Etc3RyZWFtcy13aGVuLXlvdS1hY3R1YWxseS1uZWVkLWEtcXVldWV8fGh0dHBzOi8vd3d3LmthaS13YWVobmVyLmRlL2Jsb2cvMjAyNi8wOC8yNC93aGVuLW5vdC10by11c2Utc3RyZWFtLXByb2Nlc3NpbmctbWVzc2FnaW5nLWFuZC1hcGlzLWFyZS1vZnRlbi1lbm91Z2gvP3V0bV9zb3VyY2U9YnJpZWYtdGVjaC1uZXdzLmNvbQ) is the kind of architecture-team reading list material that gets passed around Slack for a reason. He defines stream processing narrowly: data-arrival-initiated continuous computation over unbounded events, Flink, Kafka Streams, Spark Structured Streaming. He then argues it is only the right tool for stateless transformation, stateful streaming, complex event processing, and real-time ML inference. Everywhere else, call it what it is: a request-response API call, a state query, a correction flow, or a lock. Two concrete cases back the argument. Kestra 2.0 ripped out Kafka Streams and rebuilt around plain queueing. Confluent Control Center was rearchitected in May 2025 around Prometheus. If your team has a "we need a stream processor" slide in the next design review, read this first.

Ben Thompson's [Autonomy and Innovation](https://ecommerce-api.datafortress.cloud/r/brieftechnews/Ngmk8XRDWW4yzOPkiqKVnw/djF8d2VifDIwMjYtMDgtMjUtaXR8ZGVmZW5kZXJzLW5lZWQtdGhlLXNhbWUtbW9kZWwtYWNjZXNzLWFzLWF0dGFja2Vycy1zdHJhdGVjaGVyeS1hcmd1ZXN8fGh0dHBzOi8vc3RyYXRlY2hlcnkuY29tLzIwMjYvYXV0b25vbXktYW5kLWlubm92YXRpb24vP3V0bV9zb3VyY2U9YnJpZWYtdGVjaC1uZXdzLmNvbQ) essay uses the white-hat/black-hat framing to argue that AI capability is separable from intent. Defensive AI needs the same offensive access to vulnerabilities, and the only viable move is making sure defenders have equivalent access to top models. Thompson criticises the Trump administration's response to Anthropic's Fable release and to the earlier Hugging Face attack, noting that Hugging Face repelled the attack with help from open-weight Chinese models. The parallel he draws is bug bounties: build the incentive structure so the defensive side has the same firepower. Operationally, the takeaway is that any enterprise security programme that treats model access as a procurement decision rather than a defensive capability is going to be on the wrong side of the asymmetry.
