AI agents are writing cleaner code, but the mess is migrating. [New benchmarks from Gabe Orlanski](https://ecommerce-api.datafortress.cloud/r/brieftechnews/Si58rdqW4V4dcUChofg_ZA/djF8d2VifDIwMjYtMTEtMTMtdGVjaHxzbG9wLWlzLW1vdmluZy11cC10aGUtc3RhY2t8fGh0dHBzOi8vZ2FiZW9ybGFuc2tpLmdpdGh1Yi5pby9wb3N0cy9zbG9wLW1vdmVzLXVwLz91dG1fc291cmNlPWJyaWVmLXRlY2gtbmV3cy5jb20) show frontier agents now solve significantly more SlopCodeBench checkpoints while producing less slop at the code level. The problem: slop has moved up the stack into design decisions. The new LibraryDesignBench and LibraryUseBench reveal that agents lack foresight about how their code will be used -- they show poor abstraction design and completely disregard reusing library-provided code.

Solve rates on SlopCodeBench continue climbing across all three test tiers (strict, isolated, and core). But the benchmarks expose a different failure mode: an agent that writes correct code with terrible architecture is arguably worse than one that writes sloppy code you can review. The abstraction problem is the harder one to fix, because it requires judgment about future use cases, not just syntax.

[An essay on Astral Codex Ten](https://ecommerce-api.datafortress.cloud/r/brieftechnews/P1Zh5hrNqKdyNtSZpTXtjQ/djF8d2VifDIwMjYtMTEtMTMtdGVjaHxhaS1jb21wYW55LWVtcGxveWVlcy1zaG91bGQtdW5pb25pemV8fGh0dHBzOi8vd3d3LmFzdHJhbGNvZGV4dGVuLmNvbS9wL2FpLWNvbXBhbnktZW1wbG95ZWVzLXNob3VsZC11bmlvbml6ZT91dG1fc291cmNlPWJyaWVmLXRlY2gtbmV3cy5jb20) argues that skilled AI researchers are scarce enough that a dozen top researchers threatening to walk would force companies to negotiate without needing formal union recognition. For engineers who worry about what they're building, the essay makes a pragmatic case that collective action is the only lever that moves companies.

<p class="small mb-4"><a href="https://ecommerce-api.datafortress.cloud/r/brieftechnews/oKJS0scO2PX4JIJrNlc22A/djF8d2VifDIwMjYtMTEtMTMtdGVjaHxydXN0LTExMDAwLXRoZS1uZXZlci10eXBlLWZpbmFsbHktc2hpcHN8fGh0dHBzOi8vYmxvZy5ydXN0LWxhbmcub3JnLzIwMjYvMTEvMTIvUnVzdC0xLjEwMC4wLz91dG1fc291cmNlPWJyaWVmLXRlY2gtbmV3cy5jb20" target="_blank" rel="noopener noreferrer">Source: blog.rust-lang.org ↗</a></p>

Ten years and five failed attempts later, [Rust 1.100.0 stabilizes the never type (`!`)](https://ecommerce-api.datafortress.cloud/r/brieftechnews/oKJS0scO2PX4JIJrNlc22A/djF8d2VifDIwMjYtMTEtMTMtdGVjaHxydXN0LTExMDAwLXRoZS1uZXZlci10eXBlLWZpbmFsbHktc2hpcHN8fGh0dHBzOi8vYmxvZy5ydXN0LWxhbmcub3JnLzIwMjYvMTEvMTIvUnVzdC0xLjEwMC4wLz91dG1fc291cmNlPWJyaWVmLXRlY2gtbmV3cy5jb20). This is the canonical uninhabited type for diverging computations, and now you can name it anywhere, including in generic parameters like `Result<T, !>`. The release also changes `Infallible` to be an alias to the never type, which required a breaking change to the "never type fallback" from `()` to `!` in editions before 2024. The release also includes the Allocator and DropGuard APIs and conjuring zero types. If you're on an older edition, check the migration notes before upgrading.
