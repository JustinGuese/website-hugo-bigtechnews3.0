<h2 id="apache-http-servers-http2-race-condition-is-a-patch-now-situation">Apache HTTP Server&#x27;s HTTP/2 race condition is a patch-now situation</h2>

CVE-2026-119618 is a critical remote code execution vulnerability in `mod_http2`, Apache HTTP Server's HTTP/2 module. The bug is a race condition in the `assign_headers()` function that leads to heap corruption, and successful exploitation lets an unauthenticated remote attacker execute arbitrary code. No exploit is public yet, but Wiz's telemetry shows 64% of cloud environments have vulnerable resources and 51% have publicly exposed instances - that's a lot of attack surface waiting for someone to write a PoC.

Affected versions are Apache HTTP Server 2.4.55 through 2.4.70, patched in 2.4.71 and later, plus mod_h2 2.0.8 through 2.0.42, patched in 2.0.42+. If you can't upgrade immediately, disabling HTTP/2 support is the mitigation. For anyone running a default Apache install behind a load balancer that terminates TLS, check whether HTTP/2 is even negotiated before assuming you're safe - the module can still be loaded and vulnerable even if you think you're only serving HTTP/1.1.

Google published a [reference architecture for running CodeMender](https://ecommerce-api.datafortress.cloud/r/brieftechnews/J6yOaJckamZIoesYzbVLqQ/djF8d2VifDIwMjYtMTEtMTMtZGV2b3BzfGNvZGVtZW5kZXItc3RvcHMtZmxhZ2dpbmctYW5kLXN0YXJ0cy1maXhpbmctaW4teW91ci1wdWxsLXJlcXVlc3RzfHxodHRwczovL2Nsb3VkLmdvb2dsZS5jb20vYmxvZy9wcm9kdWN0cy9pZGVudGl0eS1zZWN1cml0eS9ob3ctdG8tcnVuLWNvZGVtZW5kZXItaW4teW91ci1wdWxsLXJlcXVlc3RzLz91dG1fc291cmNlPWJyaWVmLXRlY2gtbmV3cy5jb20), its autonomous code-security agent, directly in Git pull requests via Cloud Run. The workflow is slash commands in the PR timeline: `/verify` runs an exploit simulation in a sandbox to confirm whether a finding is actually exploitable, and `/fix` generates a proposed code diff with a draft pull request. Findings come back with confidence scores, and verification results can change severity assessments - meaning the tool can downgrade a false positive before a human ever looks at it.

This addresses a real operational problem: the average developer fix time for software flaws has expanded from 59 days a decade ago to over 170 days in 2025. The security team flags, the developer ignores, the ticket rots. CodeMender's model collapses that loop into a single PR comment. The architecture uses short-lived OIDC tokens rather than stored keys, so you're not adding a new secret to rotate.

Lyft [open-sourced its approach to payment testing](https://ecommerce-api.datafortress.cloud/r/brieftechnews/Dw8oo88KljHfmd3jxgGzNA/djF8d2VifDIwMjYtMTEtMTMtZGV2b3BzfGx5ZnRzLWZha2UtcGF5bWVudC1wcm92aWRlci10ZXN0cy13aGF0LXRlc3QtY2FyZHMtY2FudHx8aHR0cHM6Ly9lbmcubHlmdC5jb20vYmV5b25kLXRlc3QtY2FyZHMtYS1mYWtlLXBheW1lbnQtcHJvdmlkZXItZm9yLXRlc3RpbmctYXQtc2NhbGUtYzY5ZGRkYWRiMTE1P3NvdXJjZT1yc3MtLS0tMjVjZDM3OWFiYjgtLS00JnV0bV9zb3VyY2U9YnJpZWYtdGVjaC1uZXdzLmNvbQ) at scale. Standard test cards from card networks can simulate a decline or an approval, but they can't model partial authorization, latent captures, or refunds - the failure modes that actually break payment integrations in production. Lyft's Fake Payment Provider embeds scenario logic directly into the payment token, so a simulated user can test a specific retry or fallback path safely in both staging and production.

For anyone who has debugged a payment integration at 2am because a capture arrived three hours after the authorization, this is the pattern you wish you'd built. The token carries the scenario, the provider executes it, and the surrounding retry logic gets exercised against a deterministic failure instead of a flaky sandbox.

Heroku Postgres standard tiers don't offer logical replication or WAL access, which makes migrating large databases a multi-hour downtime event. [PlanetScale built an open source Heroku Migrator](https://ecommerce-api.datafortress.cloud/r/brieftechnews/4K8GYO-DxeaEy8qGCPhVtw/djF8d2VifDIwMjYtMTEtMTMtZGV2b3BzfHBsYW5ldHNjYWxlLW1pZ3JhdGVzLXRlcmFieXRlcy1vZmYtaGVyb2t1LXdpdGhvdXQtbG9naWNhbC1yZXBsaWNhdGlvbnx8aHR0cHM6Ly9wbGFuZXRzY2FsZS5jb20vYmxvZy9taWdyYXRlLWZyb20taGVyb2t1LXRvLXBsYW5ldHNjYWxlP3V0bV9zb3VyY2U9YnJpZWYtdGVjaC1uZXdzLmNvbQ) that sidesteps the limitation entirely. The tool uses trigger-based replication to record changes on every table and replay them on the target, providing a replication-based experience without extended downtime. Version 2.0 splits the process into data transfer and index rebuild phases, which increases copy speeds by roughly five times.

For teams stuck on Heroku's standard plans, this is the difference between a scheduled maintenance window and a live migration. The tool is open source, so you can run it against any target, not just PlanetScale.

<p class="small mb-4"><a href="https://ecommerce-api.datafortress.cloud/r/brieftechnews/aBwEUwAyNrpWRY1MDCJ48w/djF8d2VifDIwMjYtMTEtMTMtZGV2b3BzfG9wZW4tY2x1c3Rlci1tYW5hZ2VtZW50LWdyYWR1YXRlcy10by1jbmNmLWluY3ViYXRpbmd8fGh0dHBzOi8vd3d3LmNuY2YuaW8vYmxvZy8yMDI2LzExLzEwL29wZW4tY2x1c3Rlci1tYW5hZ2VtZW50LW9jbS1iZWNvbWVzLWEtY25jZi1pbmN1YmF0aW5nLXByb2plY3QvP3V0bV9zb3VyY2U9YnJpZWYtdGVjaC1uZXdzLmNvbQ" target="_blank" rel="noopener noreferrer">Source: cncf.io ↗</a></p>

The CNCF Technical Oversight Committee accepted [Open Cluster Management as an incubating project](https://ecommerce-api.datafortress.cloud/r/brieftechnews/aBwEUwAyNrpWRY1MDCJ48w/djF8d2VifDIwMjYtMTEtMTMtZGV2b3BzfG9wZW4tY2x1c3Rlci1tYW5hZ2VtZW50LWdyYWR1YXRlcy10by1jbmNmLWluY3ViYXRpbmd8fGh0dHBzOi8vd3d3LmNuY2YuaW8vYmxvZy8yMDI2LzExLzEwL29wZW4tY2x1c3Rlci1tYW5hZ2VtZW50LW9jbS1iZWNvbWVzLWEtY25jZi1pbmN1YmF0aW5nLXByb2plY3QvP3V0bV9zb3VyY2U9YnJpZWYtdGVjaC1uZXdzLmNvbQ), moving it up from the Sandbox it joined in November 2021. OCM uses a hub-and-spoke architecture with open APIs to manage Kubernetes clusters across cloud, on-premises, and edge. The asynchronous pull model maintains cluster autonomy without centralizing credentials, which matters for edge deployments where connectivity is intermittent.

Originally developed by IBM and Red Hat, it hit 1.0 in June 2025 and has since delivered updates through 1.4 in October 2026. Key features include CEL-based cluster selection, an Argo CD pull model add-on, and a pluggable add-on framework. eBay reportedly uses it with Argo CD across more than 190 clusters - a solid real-world reference for multi-cluster management at scale.

<h2 id="linkerds-independent-threat-model-found-30-threats-one-bug"><a href="https://ecommerce-api.datafortress.cloud/r/brieftechnews/MN3a4sb_yRbGRbKZ3hNZvA/djF8d2VifDIwMjYtMTEtMTMtZGV2b3BzfGxpbmtlcmRzLWluZGVwZW5kZW50LXRocmVhdC1tb2RlbC1mb3VuZC0zMC10aHJlYXRzLW9uZS1idWd8fGh0dHBzOi8vbGlua2VyZC5pby8yMDI2LzExLzEwL3doYXQtYW4taW5kZXBlbmRlbnQtdGhyZWF0LW1vZGVsLWZvdW5kLWluLWxpbmtlcmQtYW5kLXdoYXQteW91LXNob3VsZC1kby1uZXh0Lz91dG1fc291cmNlPWJyaWVmLXRlY2gtbmV3cy5jb20" target="_blank" rel="noopener noreferrer">Linkerd&#x27;s independent threat model found 30 threats, one bug</a></h2>

<p class="small mb-4"><a href="https://ecommerce-api.datafortress.cloud/r/brieftechnews/MN3a4sb_yRbGRbKZ3hNZvA/djF8d2VifDIwMjYtMTEtMTMtZGV2b3BzfGxpbmtlcmRzLWluZGVwZW5kZW50LXRocmVhdC1tb2RlbC1mb3VuZC0zMC10aHJlYXRzLW9uZS1idWd8fGh0dHBzOi8vbGlua2VyZC5pby8yMDI2LzExLzEwL3doYXQtYW4taW5kZXBlbmRlbnQtdGhyZWF0LW1vZGVsLWZvdW5kLWluLWxpbmtlcmQtYW5kLXdoYXQteW91LXNob3VsZC1kby1uZXh0Lz91dG1fc291cmNlPWJyaWVmLXRlY2gtbmV3cy5jb20" target="_blank" rel="noopener noreferrer">Source: linkerd.io ↗</a></p>

ControlPlane, a cloud native security consultancy, [built an independent threat model of open source Linkerd](https://ecommerce-api.datafortress.cloud/r/brieftechnews/MN3a4sb_yRbGRbKZ3hNZvA/djF8d2VifDIwMjYtMTEtMTMtZGV2b3BzfGxpbmtlcmRzLWluZGVwZW5kZW50LXRocmVhdC1tb2RlbC1mb3VuZC0zMC10aHJlYXRzLW9uZS1idWd8fGh0dHBzOi8vbGlua2VyZC5pby8yMDI2LzExLzEwL3doYXQtYW4taW5kZXBlbmRlbnQtdGhyZWF0LW1vZGVsLWZvdW5kLWluLWxpbmtlcmQtYW5kLXdoYXQteW91LXNob3VsZC1kby1uZXh0Lz91dG1fc291cmNlPWJyaWVmLXRlY2gtbmV3cy5jb20) and found 30 threats, 28 of them medium or high severity, plus 33 recommendations. The striking part: only one finding is an actual software bug - CVE-2025-43915, a metrics issue fixed in edge-25.2.1 by turning off affected metric labels by default. Everything else stems from default settings, operational processes, underlying Kubernetes cluster configuration, and surrounding tools like ingress controllers.

That's a useful data point for anyone evaluating service meshes: the code is solid, but the defaults and the surrounding ecosystem are where the risk lives. The review maps threats to MITRE ATT&CK and NIST 800-53 frameworks, though it didn't include penetration testing or code audits.

<p class="small mb-4"><a href="https://ecommerce-api.datafortress.cloud/r/brieftechnews/l8s_iqKm8OpJXB7QN7-UNg/djF8d2VifDIwMjYtMTEtMTMtZGV2b3BzfGdpdGh1Yi1zZWNyZXQtc2Nhbm5pbmctbm93LXdhdGNoZXMtYWN0aW9ucy13b3JrZmxvdy1sb2dzfHxodHRwczovL2dpdGh1Yi5ibG9nL2NoYW5nZWxvZy8yMDI2LTExLTA5LXNlY3JldC1zY2FubmluZy1kZXRlY3RzLXNlY3JldHMtaW4tZ2l0aHViLWFjdGlvbnMtd29ya2Zsb3ctbG9ncy8_dXRtX3NvdXJjZT1icmllZi10ZWNoLW5ld3MuY29t" target="_blank" rel="noopener noreferrer">Source: github.blog ↗</a></p>

[GitHub's secret scanning now detects secrets in Actions workflow logs](https://ecommerce-api.datafortress.cloud/r/brieftechnews/l8s_iqKm8OpJXB7QN7-UNg/djF8d2VifDIwMjYtMTEtMTMtZGV2b3BzfGdpdGh1Yi1zZWNyZXQtc2Nhbm5pbmctbm93LXdhdGNoZXMtYWN0aW9ucy13b3JrZmxvdy1sb2dzfHxodHRwczovL2dpdGh1Yi5ibG9nL2NoYW5nZWxvZy8yMDI2LTExLTA5LXNlY3JldC1zY2FubmluZy1kZXRlY3RzLXNlY3JldHMtaW4tZ2l0aHViLWFjdGlvbnMtd29ya2Zsb3ctbG9ncy8_dXRtX3NvdXJjZT1icmllZi10ZWNoLW5ld3MuY29t), available in public preview for enterprises on GitHub Enterprise Cloud with Secret Protection or GitHub Advanced Security. When a workflow run completes, GitHub scans the logs for provider patterns and raises repository alerts with links back to the offending log. The feature is disabled by default and must be enabled by enterprise owners in Advanced Security policies.

The caveats matter: only workflow runs completed after enabling the feature are scanned, and generic patterns, custom patterns, AI-detected secrets, and already-masked secrets aren't detected. If a secret leaked in a log from last month, this won't find it retroactively.

<h2 id="istio-1320-brings-gateway-api-authorization-and-east-west-unification"><a href="https://ecommerce-api.datafortress.cloud/r/brieftechnews/G88Pqvz7T2TO8TNakoR3yw/djF8d2VifDIwMjYtMTEtMTMtZGV2b3BzfGlzdGlvLTEzMjAtYnJpbmdzLWdhdGV3YXktYXBpLWF1dGhvcml6YXRpb24tYW5kLWVhc3Qtd2VzdC11bmlmaWNhdGlvbnx8aHR0cHM6Ly9pc3Rpby5pby9sYXRlc3QvbmV3cy9yZWxlYXNlcy8xLjMyLngvYW5ub3VuY2luZy0xLjMyLz91dG1fc291cmNlPWJyaWVmLXRlY2gtbmV3cy5jb20" target="_blank" rel="noopener noreferrer">Istio 1.32.0 brings Gateway API authorization and east-west unification</a></h2>

<p class="small mb-4"><a href="https://ecommerce-api.datafortress.cloud/r/brieftechnews/G88Pqvz7T2TO8TNakoR3yw/djF8d2VifDIwMjYtMTEtMTMtZGV2b3BzfGlzdGlvLTEzMjAtYnJpbmdzLWdhdGV3YXktYXBpLWF1dGhvcml6YXRpb24tYW5kLWVhc3Qtd2VzdC11bmlmaWNhdGlvbnx8aHR0cHM6Ly9pc3Rpby5pby9sYXRlc3QvbmV3cy9yZWxlYXNlcy8xLjMyLngvYW5ub3VuY2luZy0xLjMyLz91dG1fc291cmNlPWJyaWVmLXRlY2gtbmV3cy5jb20" target="_blank" rel="noopener noreferrer">Source: istio.io ↗</a></p>

[Istio 1.32.0 is out](https://ecommerce-api.datafortress.cloud/r/brieftechnews/G88Pqvz7T2TO8TNakoR3yw/djF8d2VifDIwMjYtMTEtMTMtZGV2b3BzfGlzdGlvLTEzMjAtYnJpbmdzLWdhdGV3YXktYXBpLWF1dGhvcml6YXRpb24tYW5kLWVhc3Qtd2VzdC11bmlmaWNhdGlvbnx8aHR0cHM6Ly9pc3Rpby5pby9sYXRlc3QvbmV3cy9yZWxlYXNlcy8xLjMyLngvYW5ub3VuY2luZy0xLjMyLz91dG1fc291cmNlPWJyaWVmLXRlY2gtbmV3cy5jb20), managed by release managers from Microsoft, Tetrate, and Solo.io. The headline feature is experimental AuthorizationPolicy targeting Gateway API HTTPRoute resources via `targetRefs`, which finally lets you attach authorization policies to routes rather than just gateways and services. TLS tuning on gateways gets `alpnProtocols` and `ecdhCurves` configuration, and there's a unified east-west gateway for mixed ambient and sidecar meshes.

Traffic management additions include utilization-based load balancing using ORCA load reports, richer outlier detection with configurable HTTP error codes and failure percentage thresholds, and configurable inbound retry policies. Security features include the ability to mark JWT rules as REQUIRED in RequestAuthentication. For anyone running mixed ambient and sidecar meshes, the unified east-west gateway removes a real operational headache.
