<p class="small mb-4"><a href="https://ecommerce-api.datafortress.cloud/r/brieftechnews/_f1Iq3Xvc8iIy_YgJzfK2A/djF8d2VifDIwMjYtMTAtMjMtZGV2b3BzfHdoeS1vbi1kZWxldGUtY2FzY2FkZS1raWxscy1kYXRhYmFzZS1hdmFpbGFiaWxpdHl8fGh0dHBzOi8vcGxhbmV0c2NhbGUuY29tL2Jsb2cvaS1kb250LWxpa2UtZGVsZXRlLWNhc2NhZGU_dXRtX3NvdXJjZT1icmllZi10ZWNoLW5ld3MuY29t" target="_blank" rel="noopener noreferrer">Source: planetscale.com ↗</a></p>

PlanetScale highlighted a classic relational database footgun in [I Don't Trust ON DELETE CASCADE](https://ecommerce-api.datafortress.cloud/r/brieftechnews/_f1Iq3Xvc8iIy_YgJzfK2A/djF8d2VifDIwMjYtMTAtMjMtZGV2b3BzfHdoeS1vbi1kZWxldGUtY2FzY2FkZS1raWxscy1kYXRhYmFzZS1hdmFpbGFiaWxpdHl8fGh0dHBzOi8vcGxhbmV0c2NhbGUuY29tL2Jsb2cvaS1kb250LWxpa2UtZGVsZXRlLWNhc2NhZGU_dXRtX3NvdXJjZT1icmllZi10ZWNoLW5ld3MuY29t). While cascading deletes simplify application logic by removing child records automatically, they introduce unpredictable locking behavior at scale. 

The core issue comes down to lock contention. In PostgreSQL, a large cascade holds a `RowExclusiveLock` across multiple related tables while the operation completes, generating massive Write-Ahead Log (WAL) volume and keeping transactions open. If a separate migration attempts a simple `ALTER TABLE` during this window, it requests an `AccessExclusiveLock`, queuing up behind the cascade. Subsequent queries then queue behind the blocked migration, rapidly consuming connection pools and triggering an outage. The post recommends enforcing explicit soft deletes, pairing them with bounded, batched background cleanup workers, and keeping migrations protected with strict `lock_timeout` settings.

GitHub has placed [Workflow Lockfiles in public preview](https://ecommerce-api.datafortress.cloud/r/brieftechnews/OWY2eFU7BsjACBmqTULYeA/djF8d2VifDIwMjYtMTAtMjMtZGV2b3BzfGdpdGh1Yi1hY3Rpb25zLWFkZHMtbmF0aXZlLWNvbW1pdC1sb2NrZmlsZXN8fGh0dHBzOi8vZ2l0aHViLmJsb2cvY2hhbmdlbG9nLzIwMjYtMTAtMTQtZ2l0aHViLWFjdGlvbnMtd29ya2Zsb3ctbG9ja2ZpbGVzLWluLXB1YmxpYy1wcmV2aWV3Lz91dG1fc291cmNlPWJyaWVmLXRlY2gtbmV3cy5jb20) across all account tiers. Pointing CI workflows at mutable git tags like `@v4` introduces severe supply-chain risks, as an attacker compromising an upstream action repository can move the tag to point at malicious code. Pinning to full SHA hashes solves the security problem but makes workflow files unreadable and difficult to maintain.

Workflow lockfiles resolve this trade-off. Workflows can still reference human-readable tags, while a local `.github/workflows/actions.lock` file pins actions and reusable workflows to their immutable Git commit hashes. Platform engineers can manage these files via the `gh actions-lock` CLI extension, automate updates using Dependabot, and enforce an organization-wide `Require lockfile` policy to block untracked action execution.

A benchmark conducted by Radar and published by the CNCF makes a strong case for context over specialized tooling: [Before you evaluate an AI SRE, give your existing agent context](https://ecommerce-api.datafortress.cloud/r/brieftechnews/GntyrstD9yyMjeevbiQHmA/djF8d2VifDIwMjYtMTAtMjMtZGV2b3BzfGdpdmluZy1jb2RpbmctYWdlbnRzLXJlYWQtb25seS1jbHVzdGVyLWNvbnRleHR8fGh0dHBzOi8vd3d3LmNuY2YuaW8vYmxvZy8yMDI2LzEwLzIxL2JlZm9yZS15b3UtZXZhbHVhdGUtYW4tYWktc3JlLWdpdmUteW91ci1leGlzdGluZy1hZ2VudC1jb250ZXh0Lz91dG1fc291cmNlPWJyaWVmLXRlY2gtbmV3cy5jb20). Running Microsoft’s SREGym benchmark across 50 simulated fault scenarios on an Amazon EKS cluster, researchers compared standard Claude Code using a bash shell against the same agent equipped with read-only Model Context Protocol (MCP) access to cluster state.

Raw diagnostic accuracy barely budged: 46 correct diagnoses with context versus 45 without. But the diagnostic speed changed drastically. Agents equipped with MCP context solved 86% of the faults within two minutes, compared to 60% for the shell-only agents. Median time-to-diagnosis fell from 87 seconds down to 44 seconds. Before buying complex "autonomous SRE" platforms, teams should test whether standard coding agents simply need structured, low-latency API context to do the same job.

The incident exposed weak private keys, theoretically granting attackers the ability to mint forged, trusted TLS certificates for arbitrary domains.

Cloudflare quickly patched its edge proxy, Zero Trust, and Tunnel systems, while purging the compromised certificates from internal trust stores. However, edge-level revocations do not fully protect client-side software relying on bundled trust anchors. Administrators must ensure mobile and desktop endpoints upgrade immediately to Cloudflare One Client v2.5.7 on Android, v1.12.7 on iOS, and the corresponding updated desktop builds to avoid trust validation exploits.
