The stickiness is the part that matters. More than half of consumers who make one agentic purchase come back for a second, typically in the same spending category. That's a repeat-purchase pattern that looks less like novelty and more like habit formation. If you're building for consumers, the question is no longer whether agents will transact - it's whether your product is the one they'll reach for when the agent goes shopping.

Price per token has dropped 80% since January 2025, per OpenRouter data, and [pass-through pricing](https://ecommerce-api.datafortress.cloud/r/brieftechnews/XadL5B7p_UnnDLaWqYSsrQ/djF8d2VifDIwMjYtMTEtMjMtZm91bmRlcnN8cGFzcy10aHJvdWdoLXByaWNpbmctdGhlLW5ldy1kZWZhdWx0LWZvci1haS1zYWFzfHxodHRwczovL3d3dy5ncm93dGh1bmhpbmdlZC5jb20vcC9wYXNzLXRocm91Z2gtcHJpY2luZy1mb3ItYWk_dXRtX3NvdXJjZT1icmllZi10ZWNoLW5ld3MuY29t) is the response. Anthropic launched linked billing in beta on November 17th, letting platforms like Asana and Linear pass Claude API costs directly to end customers. That decouples AI spend from platform costs and makes the economics transparent.

Gumloop already made the switch: it passes token and compute costs through plus an 8% orchestration fee, with a separate enterprise platform fee. The result was a 42% rise in Pro trial conversion, and open-weight models grew from nothing to a real share of usage. The tradeoffs are real - Gumloop gives up pricing control since token revenue now moves with outside model prices, and existing contracts stay in place until renewal. But for a market where customers are fleeing to cheaper open models, transparency is looking like the only durable pricing strategy.

Harrison Chase argues the missing piece for making AI work in companies [isn't better models or more context - it's better knowledge](https://ecommerce-api.datafortress.cloud/r/brieftechnews/54JFOWi4AK-ArJ0V23EFhA/djF8d2VifDIwMjYtMTEtMjMtZm91bmRlcnN8YnVpbGRpbmctYS1rbm93bGVkZ2UtZmFjdG9yeS1ub3QtanVzdC1tb3JlLWNvbnRleHR8fGh0dHBzOi8veC5jb20vaHdjaGFzZTE3L3N0YXR1cy8yMTI0MTgxMjE2NzE5MTUxNTg1P3V0bV9zb3VyY2U9YnJpZWYtdGVjaC1uZXdzLmNvbQ). The analogy is a software factory: instead of building software, you build the systems that help agents perform general knowledge work. For anyone running agents in production, this is the difference between a demo and a durable system. Agents don't need more context; they need the right context, curated and maintained.

[Vercel Functions now support inbound request bodies up to 20MiB](https://ecommerce-api.datafortress.cloud/r/brieftechnews/V16Lb0dN3rjmTkj0QmSZDg/djF8d2VifDIwMjYtMTEtMjMtZm91bmRlcnN8dmVyY2VsLWZ1bmN0aW9ucy1ncm93LXVwLTIwbWliLXJlcXVlc3QtYm9kaWVzfHxodHRwczovL3ZlcmNlbC5jb20vY2hhbmdlbG9nL3ZlcmNlbC1mdW5jdGlvbnMtbm93LXN1cHBvcnQtcmVxdWVzdC1ib2RpZXMtdXAtdG8tMjBtaWI_dXRtX3NvdXJjZT1icmllZi10ZWNoLW5ld3MuY29t), up from 4.5MB, in public beta. This is opt-in via the `VERCEL_SUPPORT_LARGE_REQUEST_BODY=1` environment variable, requires the 4GB performance memory setting, and applies to Node.js, Python, and Bun runtimes. Edge runtime functions keep the 4.5MB cap, and Routing Middleware will receive headers but no body to avoid sending data twice.

The practical impact: you can now ship file uploads, large JSON payloads, and AI-generated content through Functions without the old workarounds. The tradeoff is the 4GB memory requirement - that's a real cost increase for high-traffic functions, so benchmark before you flip the flag.
