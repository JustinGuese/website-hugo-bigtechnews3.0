[Poppy 1.0](https://ecommerce-api.datafortress.cloud/r/brieftechnews/Ls84n_-3cy7G2yBxRf5d0Q/djF8d2VifDIwMjYtMTEtMTctaXR8cG9wcHktMTAtZ2l2ZXMtYWdlbnRzLWEtc3RhbmRhcmQtd2F5LXRvLXRyYW5zYWN0fHxodHRwczovL3NpZXJyYS5haS9ibG9nL3JlbGVhc2luZy1wb3BweT91dG1fc291cmNlPWJyaWVmLXRlY2gtbmV3cy5jb20) is a protocol that lets personal AI agents interact with businesses through agents, websites, and APIs, with OAuth authentication on top. It builds on MCP, OpenAPI, and UCP, which means it is less a new wire format and more a contract for how agents and businesses introduce themselves, negotiate, and complete transactions.

The v1.0 release adds staged adoption so businesses can roll out support incrementally, plus refined standards usage and a commerce extension co-authored by Shopify. That last part matters: Shopify enabled Poppy for all merchants, and design partners including Delta, Salesforce, and Zoom have joined, with over 100 total. When the largest e-commerce platform ships protocol support by default, the network effect kicks in fast. For engineers, this is the first credible answer to the question of how agents authenticate to your systems without handing over API keys to every LLM wrapper that asks.

For anyone running a migration or integration project, this is the reminder that your vendors' security posture is your security posture. Audit the access you grant, and assume it will be abused.

<p class="small mb-4"><a href="https://ecommerce-api.datafortress.cloud/r/brieftechnews/0kqPro4QPdnyvMyfDtunWA/djF8d2VifDIwMjYtMTEtMTctaXR8dW5pdC10ZXN0cy1zdGlsbC1tYXR0ZXItd2hlbi1hZ2VudHMtd3JpdGUtdGhlLWNvZGV8fGh0dHBzOi8vZG9jc3ByaW5nLmNvbS9ibG9nL3Bvc3RzL3VuaXQtdGVzdHMtYWktYWdlbnRzLz91dG1fc291cmNlPWJyaWVmLXRlY2gtbmV3cy5jb20" target="_blank" rel="noopener noreferrer">Source: docspring.com ↗</a></p>

[DocSpring analyzed a month of CI history and Claude Code transcripts](https://ecommerce-api.datafortress.cloud/r/brieftechnews/0kqPro4QPdnyvMyfDtunWA/djF8d2VifDIwMjYtMTEtMTctaXR8dW5pdC10ZXN0cy1zdGlsbC1tYXR0ZXItd2hlbi1hZ2VudHMtd3JpdGUtdGhlLWNvZGV8fGh0dHBzOi8vZG9jc3ByaW5nLmNvbS9ibG9nL3Bvc3RzL3VuaXQtdGVzdHMtYWktYWdlbnRzLz91dG1fc291cmNlPWJyaWVmLXRlY2gtbmV3cy5jb20) to test whether unit tests matter when AI agents write code. Useful tests checked decided rules; costly ones were mostly snapshot tests that repeated implementation. One snapshot test was updated 24 times without catching anything.

The key insight: tests describing what code does are meaningless if the agent misunderstood the requirement, because code and test fail in the same way. Tests that enforce explicit rules and run real engines catch critical bugs. The takeaway is not to delete your test suite, but to delete the tests that just mirror the implementation.

<h2 id="agents-need-an-undo-button-not-more-approval-prompts"><a href="https://ecommerce-api.datafortress.cloud/r/brieftechnews/d1aJeed8UmIRCq48EZbA1w/djF8d2VifDIwMjYtMTEtMTctaXR8YWdlbnRzLW5lZWQtYW4tdW5kby1idXR0b24tbm90LW1vcmUtYXBwcm92YWwtcHJvbXB0c3x8aHR0cHM6Ly9xdWFzcGFyLmNvbS9yZXNvdXJjZXMvYWdlbnRzLW5lZWQtYW4tdW5kby1idXR0b24_dXRtX3NvdXJjZT1icmllZi10ZWNoLW5ld3MuY29t" target="_blank" rel="noopener noreferrer">Agents need an undo button, not more approval prompts</a></h2>

<p class="small mb-4"><a href="https://ecommerce-api.datafortress.cloud/r/brieftechnews/d1aJeed8UmIRCq48EZbA1w/djF8d2VifDIwMjYtMTEtMTctaXR8YWdlbnRzLW5lZWQtYW4tdW5kby1idXR0b24tbm90LW1vcmUtYXBwcm92YWwtcHJvbXB0c3x8aHR0cHM6Ly9xdWFzcGFyLmNvbS9yZXNvdXJjZXMvYWdlbnRzLW5lZWQtYW4tdW5kby1idXR0b24_dXRtX3NvdXJjZT1icmllZi10ZWNoLW5ld3MuY29t" target="_blank" rel="noopener noreferrer">Source: quaspar.com ↗</a></p>

[This piece argues](https://ecommerce-api.datafortress.cloud/r/brieftechnews/d1aJeed8UmIRCq48EZbA1w/djF8d2VifDIwMjYtMTEtMTctaXR8YWdlbnRzLW5lZWQtYW4tdW5kby1idXR0b24tbm90LW1vcmUtYXBwcm92YWwtcHJvbXB0c3x8aHR0cHM6Ly9xdWFzcGFyLmNvbS9yZXNvdXJjZXMvYWdlbnRzLW5lZWQtYW4tdW5kby1idXR0b24_dXRtX3NvdXJjZT1icmllZi10ZWNoLW5ld3MuY29t) that approval prompts become reflexive and ineffective over time. The alternative is treating agents as sagas with compensating steps: every tool must have a documented undo mechanism before use. Actions are categorized as reversible, compensable, or irreversible, with the latter needing stricter controls.

The sagas pattern from distributed systems maps cleanly onto agent actions. Tracking and executing undos should live in the underlying system, not inside the agent, because the agent is the thing you do not trust. This is the right framing for anyone building agent infrastructure.
