[Spacelift integrated with Cursor Origin](https://ecommerce-api.datafortress.cloud/r/brieftechnews/_YFUDQ9ljFGLW2BY7ZvLOQ/djF8d2VifDIwMjYtMTAtMTYtZGV2b3BzfHNwYWNlbGlmdC1lbmZvcmNlcy1wb2xpY3ktb24tY3Vyc29yLW9yaWdpbnx8aHR0cHM6Ly9zcGFjZWxpZnQuaW8vYmxvZy9zcGFjZWxpZnQtY3Vyc29yLW9yaWdpbi1pbnRlZ3JhdGlvbj91dG1fc291cmNlPWJyaWVmLXRlY2gtbmV3cy5jb20), extending its deployment workflows and Open Policy Agent (OPA) guardrails to Cursor's Git-like version control platform for agentic code. Origin is built specifically to handle branches and diffs synthesized by AI agents, but infrastructure teams still need the same controls they apply to GitHub, GitLab, and Bitbucket. 

Under the hood, Spacelift registers as a first-class app inside Origin using its own signing key. When an agent opens an infrastructure PR inside Origin, Spacelift validates the signature, runs the plan phase in an isolated runner, and evaluates configured OPA policies against the proposed state modifications. Approval flows, drift detection triggers, and blast-radius restrictions execute identically to human PRs. If an agent tries to open an ingress security group to `0.0.0.0/0` or spin up an unapproved instance class, Spacelift halts the run before state locks are acquired.

Engineers can now embed standard SQL queries directly into the Logpush job definition. The edge nodes process the queries inline as logs are generated: filtering out noise, nesting flat fields, renaming keys to match OpenTelemetry schemas, and redacting sensitive session IDs or authorization headers on a per-record basis. Downstream ingestion bills scale directly with byte count; dropping verbose user-agent strings or high-cardinality headers before shipping payloads to Datadog or S3 reduces operational overhead and storage costs immediately.

<p class="small mb-4"><a href="https://ecommerce-api.datafortress.cloud/r/brieftechnews/M9-apPvZ5hm5zWVoehRHpg/djF8d2VifDIwMjYtMTAtMTYtZGV2b3BzfHBsYW5ldHNjYWxlLXRhY2tsZXMtdm9sYXRpbGUtc3FsLWV4cHJlc3Npb25zLWluLW5la2l8fGh0dHBzOi8vcGxhbmV0c2NhbGUuY29tL2Jsb2cvbmVraS12b2xhdGlsZS1leHByZXNzaW9ucz91dG1fc291cmNlPWJyaWVmLXRlY2gtbmV3cy5jb20" target="_blank" rel="noopener noreferrer">Source: planetscale.com ↗</a></p>

Sharding PostgreSQL is notoriously hard because relational engines assume single-node determinism. PlanetScale's [deep dive into sequences and volatile expressions in Neki](https://ecommerce-api.datafortress.cloud/r/brieftechnews/M9-apPvZ5hm5zWVoehRHpg/djF8d2VifDIwMjYtMTAtMTYtZGV2b3BzfHBsYW5ldHNjYWxlLXRhY2tsZXMtdm9sYXRpbGUtc3FsLWV4cHJlc3Npb25zLWluLW5la2l8fGh0dHBzOi8vcGxhbmV0c2NhbGUuY29tL2Jsb2cvbmVraS12b2xhdGlsZS1leHByZXNzaW9ucz91dG1fc291cmNlPWJyaWVmLXRlY2gtbmV3cy5jb20) highlights how its sharded Postgres architecture handles operations that depend on physical time or cross-shard sequence generation. 

In standard Postgres, calling `nextval()` or `NOW()` executes within a local transaction context. In Neki, no single shard holds the entire dataset. If a distributed router evaluates an expression too early, it can execute multiple times across parallel shard scans; if evaluated too late, it breaks transaction isolation. Neki coordinates sequence generation across shards through its distributed router to guarantee unique surrogate keys without forcing strict consecutiveness, which would bottleneck writes across nodes. The router tracks expression volatility classes and ensures non-deterministic operations execute exactly as many times as the SQL specification demands.

Connecting serverless functions directly to relational databases is an easy way to exhaust connection pools and blow up latency budgets through TLS handshakes on every invocation. [Cloudflare Hyperdrive for MySQL](https://ecommerce-api.datafortress.cloud/r/brieftechnews/CGLkT7R1hl0_3Y-lK-1Uyw/djF8d2VifDIwMjYtMTAtMTYtZGV2b3BzfGNsb3VkZmxhcmUtZ2FzLWh5cGVyZHJpdmUtZm9yLW15c3FsLWFmdGVyLXByb3RvY29sLWZpeGVzfHxodHRwczovL2Jsb2cuY2xvdWRmbGFyZS5jb20vaHlwZXJkcml2ZS1teXNxbC8_dXRtX3NvdXJjZT1icmllZi10ZWNoLW5ld3MuY29t) is now generally available for Cloudflare Workers, maintaining a warm global connection pool to centralized MySQL instances and caching read queries inside the CDN.

Reaching GA required hunting down 20 deep-seated edge bugs, most notably a caching error that silently returned empty results when dealing with multi-byte emoji encodings. Cloudflare discovered the issue stemmed from an architectural assumption inherited from its PostgreSQL pooler: Hyperdrive shared cache state between connections that had negotiated different MySQL wire protocol capabilities. When a client requested a query with an encoding mismatch, the cached raw packet failed client-side deserialization. Cloudflare resolved it by serializing responses into a normalized canonical structure at the proxy layer before translating down to client-specific capability flags.

Engineers scaling agent workloads frequently hit a wall with inference runtimes: TensorRT-LLM provides top-tier hardware efficiency but remains painful to modify, while vLLM offers modular Python ergonomics at the expense of control plane latency. [TokenSpeed](https://ecommerce-api.datafortress.cloud/r/brieftechnews/h4XlONlkJwukOYYN_YWkyA/djF8d2VifDIwMjYtMTAtMTYtZGV2b3BzfGhpZ2gtdGhyb3VnaHB1dC1pbmZlcmVuY2Utd2l0aC10b2tlbnNwZWVkfHxodHRwczovL2dpdGh1Yi5jb20vbGlnaHRzZWVrb3JnL3Rva2Vuc3BlZWQ_dXRtX3NvdXJjZT1icmllZi10ZWNoLW5ld3MuY29t) is an open-source inference engine backed by the LightSeek Foundation designed to bridge that gap.

TokenSpeed splits the inference stack cleanly: its control plane is built in C++ as a deterministic finite-state machine with compile-time KV-cache safety checks, while the model execution plane runs in Python with a pluggable kernel API. Recent benchmarks claim TokenSpeed clocks 685 tokens per second on NVIDIA GB300 silicon while shaving vector workload costs by up to 90% on NVIDIA Vera Rubin and AMD Instinct hardware. The separation keeps speculative decoding and multi-step agent request scheduling out of Python's global interpreter lock.

It exposes setup targets for tools like Claude Code and Cursor, allowing engineers to pin an agent's retrieval layer to a localized, zero-cloud index running entirely on the developer's workstation or CI runner.
