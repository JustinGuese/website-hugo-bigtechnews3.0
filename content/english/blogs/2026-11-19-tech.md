<p class="small mb-4"><a href="https://ecommerce-api.datafortress.cloud/r/brieftechnews/WxZuTcmpX_Vx8HXNH2zk2Q/djF8d2VifDIwMjYtMTEtMTktdGVjaHxoYXJkd2FyZS1pcy1zb2Z0d2FyZS1hbmQtc29mdHdhcmUtaXMtZWF0aW5nLWFlcm9zcGFjZXx8aHR0cHM6Ly91bmNoYXJ0ZWR0ZXJyaXRvcmllcy50b21hc3B1ZXlvLmNvbS9wL2hhcmR3YXJlLWlzLXNvZnR3YXJlP3V0bV9zb3VyY2U9YnJpZWYtdGVjaC1uZXdzLmNvbQ" target="_blank" rel="noopener noreferrer">Source: unchartedterritories.tomaspueyo.com ↗</a></p>

Boom Supersonic CEO Blake Scholl makes the case that [hardware engineering is increasingly software engineering](https://ecommerce-api.datafortress.cloud/r/brieftechnews/WxZuTcmpX_Vx8HXNH2zk2Q/djF8d2VifDIwMjYtMTEtMTktdGVjaHxoYXJkd2FyZS1pcy1zb2Z0d2FyZS1hbmQtc29mdHdhcmUtaXMtZWF0aW5nLWFlcm9zcGFjZXx8aHR0cHM6Ly91bmNoYXJ0ZWR0ZXJyaXRvcmllcy50b21hc3B1ZXlvLmNvbS9wL2hhcmR3YXJlLWlzLXNvZnR3YXJlP3V0bV9zb3VyY2U9YnJpZWYtdGVjaC1uZXdzLmNvbQ). Most calculations are done in spreadsheets rather than as robust software systems. He argues for designing algorithms for hardware design, not just the hardware itself, enabling rapid redesign under different assumptions.

The numbers are the point: AI now lets one engineer do in realtime what previously took 100 engineers six months, and one tool auto-generates 65% of an entire aircraft structure. For anyone who has watched a hardware team spend weeks re-running a simulation because someone changed a parameter, this reframing is overdue. The practical takeaway is that hard tech companies that treat their design process as software will out-iterate those that don't.

<p class="small mb-4"><a href="https://ecommerce-api.datafortress.cloud/r/brieftechnews/r59vs2jn1LfUdp06lmaWcA/djF8d2VifDIwMjYtMTEtMTktdGVjaHx1bmJsb2NrYWJsZS1jb21tdW5pY2F0aW9uLXdpdGgtZ3Jhdml0eXx8aHR0cHM6Ly93d3cuc2NpZW5jZS5vcmcvZG9pLzEwLjExMjYvc2NpYWR2LmFlZTA4MDI_dXRtX3NvdXJjZT1icmllZi10ZWNoLW5ld3MuY29t" target="_blank" rel="noopener noreferrer">Source: science.org ↗</a></p>

Every wireless technology you use is electromagnetic, which means it can be screened, jammed, or blocked. A new study in [Science Advances proposes using gravity instead](https://ecommerce-api.datafortress.cloud/r/brieftechnews/r59vs2jn1LfUdp06lmaWcA/djF8d2VifDIwMjYtMTEtMTktdGVjaHx1bmJsb2NrYWJsZS1jb21tdW5pY2F0aW9uLXdpdGgtZ3Jhdml0eXx8aHR0cHM6Ly93d3cuc2NpZW5jZS5vcmcvZG9pLzEwLjExMjYvc2NpYWR2LmFlZTA4MDI_dXRtX3NvdXJjZT1icmllZi10ZWNoLW5ld3MuY29t). The protocol works by a broadcaster encoding a binary message through moving a mass, and a receiver detecting the gravitational signal with an off-the-shelf, hand-held gravimeter.

This is real, implemented, and slow. Gravity is weak, so data rates will be abysmal. But for scenarios where you need a channel that literally cannot be blocked - submarines, deep mines, or contested environments where RF jamming is a given - this is a fundamentally different threat model. The paper is worth reading if you care about comms resilience, but don't expect to replace your 5G link anytime soon.

[AWS announced version 1.0 of ExtendDB](https://ecommerce-api.datafortress.cloud/r/brieftechnews/yO43s0CdvL-3yV6CO3-2cw/djF8d2VifDIwMjYtMTEtMTktdGVjaHxhd3MtZXh0ZW5kZGItMTAtZHluYW1vZGItZXZlcnl3aGVyZXx8aHR0cHM6Ly9hd3MuYW1hem9uLmNvbS9hYm91dC1hd3Mvd2hhdHMtbmV3LzIwMjYvMTEvYXdzLWV4dGVuZGRiLTEtMC8_dXRtX3NvdXJjZT1icmllZi10ZWNoLW5ld3MuY29t), an open-source, DynamoDB-compatible adapter for production use. It supports four storage backends - PostgreSQL, SQLite, Cassandra, and MongoDB - and runs DynamoDB workloads on-premises, in private/public clouds, or at the edge without code rewrites. For local dev and CI, the extenddb-dev container image and @extenddb/dev npm package provide a DynamoDB-compatible endpoint over SQLite.

Apache 2.0 licensed, maintained by AWS, developed openly on GitHub. This is the kind of thing that makes DynamoDB a portable API rather than a lock-in. If you've ever had to rewrite a codebase because you wanted to leave DynamoDB, this removes that cost. The SQLite backend for local testing is a small quality-of-life win that will save a lot of CI pain.

Jacob Tomlinson describes a shift toward ["foundation software,"](https://ecommerce-api.datafortress.cloud/r/brieftechnews/Kpyabn1AqmV9aytyBjFudA/djF8d2VifDIwMjYtMTEtMTktdGVjaHxmb3VuZGF0aW9uLXNvZnR3YXJlLWZvcmtzLWFzLXRoZS1uZXctcHJ8fGh0dHBzOi8vamFjb2J0b21saW5zb24uZGV2L3Bvc3RzLzIwMjYvZm91bmRhdGlvbi1zb2Z0d2FyZS8_dXRtX3NvdXJjZT1icmllZi10ZWNoLW5ld3MuY29t) where developers fork existing tools and use AI agents to add personal features and maintain the fork against upstream releases. Agents can rebase changes and cherry-pick fixes, making forks sustainable for the first time.

The open-source implications are messy. 2026 has been a weird year: more code than ever, but also anti-AI stances and reduced community interest. The prediction here is that libraries remain critical, but simple projects get vibe-coded into personal forks. Ownership becomes personal rather than communal. Maintainers would need agents to search through forks for patterns worth merging upstream. It's a plausible future, and it changes the economics of who maintains what.

For engineers building safety-critical systems, this is a reminder that the stats you present are as important as the ones you collect.
