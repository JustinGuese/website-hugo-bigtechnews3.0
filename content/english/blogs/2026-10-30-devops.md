Datadog released [Infrastructure Basic](https://ecommerce-api.datafortress.cloud/r/brieftechnews/XB8Fm4x9vHEBAXMBFVINZA/djF8d2VifDIwMjYtMTAtMzAtZGV2b3BzfGRhdGFkb2ctc3BsaXRzLXRoZS1hZ2VudC1iaWxsLXdpdGgtaW5mcmFzdHJ1Y3R1cmUtYmFzaWN8fGh0dHBzOi8vd3d3LmRhdGFkb2docS5jb20vYmxvZy9pbmZyYXN0cnVjdHVyZS1tb25pdG9yaW5nLWJhc2ljLz91dG1fc291cmNlPWJyaWVmLXRlY2gtbmV3cy5jb20), a lower-tier monitoring option targeting non-critical infrastructure, internal tools, and staging instances. Crucially, metrics collected under Infrastructure Basic keep full-resolution retention for 15 months, matching high-tier plans for year-over-year capacity planning. It includes standard alerting profiles and out-of-the-box dashboards, alongside integrations with incident platforms like PagerDuty and ServiceNow. Teams can run Basic alongside Pro and Enterprise agents inside the same organization, meaning operators no longer have to deploy separate Prometheus or Telegraf stacks just to avoid paying full-suite prices on development boxes.

<p class="small mb-4"><a href="https://ecommerce-api.datafortress.cloud/r/brieftechnews/sybXhNW6qyGrgDlhizSCQQ/djF8d2VifDIwMjYtMTAtMzAtZGV2b3BzfGt1YmVybmV0ZXMtbGF1bmNoZXMtd29ya2xvYWQtY29uZm9ybWFuY2Utd29ya2luZy1ncm91cHx8aHR0cHM6Ly9rdWJlcm5ldGVzLmlvL2Jsb2cvMjAyNi8xMC8yNy9hbm5vdW5jaW5nLXdvcmtsb2FkLWNvbmZvcm1hbmNlLXdnLz91dG1fc291cmNlPWJyaWVmLXRlY2gtbmV3cy5jb20" target="_blank" rel="noopener noreferrer">Source: kubernetes.io ↗</a></p>

Every Kubernetes operator knows the pain of an API version surviving a minor upgrade while the runtime behavior of the workload silently degrades. Upstream is addressing this gap directly with the [Workload Conformance Working Group](https://ecommerce-api.datafortress.cloud/r/brieftechnews/sybXhNW6qyGrgDlhizSCQQ/djF8d2VifDIwMjYtMTAtMzAtZGV2b3BzfGt1YmVybmV0ZXMtbGF1bmNoZXMtd29ya2xvYWQtY29uZm9ybWFuY2Utd29ya2luZy1ncm91cHx8aHR0cHM6Ly9rdWJlcm5ldGVzLmlvL2Jsb2cvMjAyNi8xMC8yNy9hbm5vdW5jaW5nLXdvcmtsb2FkLWNvbmZvcm1hbmNlLXdnLz91dG1fc291cmNlPWJyaWVmLXRlY2gtbmV3cy5jb20).

Historically, Kubernetes conformance tests validated whether an infrastructure provider implemented the control plane and API specs correctly. They never guaranteed that identical Pod specifications behave identically across versions during node drains, network shifts, or resource exhaustion. The new working group is drafting a runtime behavior specification spanning seven areas:
* Security contexts and privilege escalation boundaries
* Workload resilience during node disruptions and eviction
* Resource scheduling and cgroup limits
* Network namespace routing and service resolution
* CSI volume attachment and lifecycle guarantees
* Controller API usage patterns
* Standardized runtime observability

The WG plans to release a binary test harness for upstream CI within two to three release cycles. The goal is simple: continuous, reproducible conformance tests that catch behavioral changes before an upgrade breaks traffic routing or graceful pod termination in production.

Supabase announced the private alpha of [Supabase Compute](https://ecommerce-api.datafortress.cloud/r/brieftechnews/v3eLcfiG17j8UZg_SEhCCw/djF8d2VifDIwMjYtMTAtMzAtZGV2b3BzfHN1cGFiYXNlLWNvbXB1dGUtbW92ZXMtYWdlbnRzLWluc2lkZS10aGUtZGF0YWJhc2UtYm91bmRhcnl8fGh0dHBzOi8vc3VwYWJhc2UuY29tL2Jsb2cvc3VwYWJhc2UtY29tcHV0ZS1wcml2YXRlLWFscGhhP3V0bV9zb3VyY2U9YnJpZWYtdGVjaC1uZXdzLmNvbQ) in `us-west-2`. The service deploys long-running containers alongside managed database instances, targeting long-lived tasks that exceed the wall-clock execution boundaries of edge functions - such as continuous background syncs, custom HTTP endpoints, and autonomous agents.

Containers provision via the Supabase CLI (`v2.120.0+`) with sizing options currently fixed at 2 GB RAM / 1 vCPU or 4 GB RAM / 2 vCPU. Services automatically inherit project secrets, network bindings, and log drains. For data-dense operations, the physical co-location avoids cross-region TLS handshakes: internal user testing showed data agent query latencies dropping from 65 ms across regions down to a median of 2.9 ms on local compute. Autoscaling is absent in the alpha, meaning workloads remain pinned to static profiles for evaluation.

Managing multi-tenant Kubernetes via GitOps frequently degrades into sprawling credential stores and cluster configuration drift. A production retrospective by Nitish Mane on [managing 34 clusters with a single Argo CD hub](https://ecommerce-api.datafortress.cloud/r/brieftechnews/MacwaS5rqrG55TtsaPWOcg/djF8d2VifDIwMjYtMTAtMzAtZGV2b3BzfHNjYWxpbmctZ2l0b3BzLW9uZS1hcmdvLWNkLWh1Yi1hY3Jvc3MtMzQtY2x1c3RlcnN8fGh0dHBzOi8vY2xvdWRuYXRpdmVub3cuY29tL2NvbnRyaWJ1dGVkLWNvbnRlbnQvb25lLWh1Yi0zNC1jbHVzdGVycy1sZXNzb25zLWZyb20tYS1naXRvcHMtY29udHJvbC1wbGFuZS1hdC1zY2FsZS8_dXRtX3NvdXJjZT1icmllZi10ZWNoLW5ld3MuY29t) details how to tame fleet sprawl across 22 AWS accounts and one Oracle Cloud tenancy.

The setup drives 1,214 Argo CD `Application` objects sourced from 174 shared Helm charts using a centralized control plane. Instead of embedding custom manifests per target, cluster onboarding is reduced to a concise declarative contract of roughly 20 YAML keys. Short-lived cross-account IAM roles handle cluster authentication, eliminating static kubeconfig tokens in the control plane. By combining pre-merge CI manifest diffs with explicit prune protections, the engineering team cut cluster onboarding time from four business days to 1.7 hours without risking accidental cascading deletions.

Engineering teams attempting to offer platform self-service without opening their state files to wild edits can look at Spacelift's blueprint for [integrating Terraform with Spotify's Backstage](https://ecommerce-api.datafortress.cloud/r/brieftechnews/mUix4xo8i0ZAUsuyDj6G0g/djF8d2VifDIwMjYtMTAtMzAtZGV2b3BzfHNlbGYtc2VydmljZS1pbmZyYXN0cnVjdHVyZS12aWEtYmFja3N0YWdlLWFuZC10ZXJyYWZvcm18fGh0dHBzOi8vc3BhY2VsaWZ0LmlvL2Jsb2cvdGVycmFmb3JtLWJhY2tzdGFnZT91dG1fc291cmNlPWJyaWVmLXRlY2gtbmV3cy5jb20). 

The architecture uses Backstage strictly as a catalog front-end and parameter collection layer. When a developer requests an RDS database or an S3 bucket via Backstage Software Templates, the portal does not execute Terraform commands directly. Instead, it generates a pull request with standardized HCL against the platform repository. The Spacelift plugin surfaces the resulting speculative plan and run status inside the Backstage UI. This keeps Git as the immutable audit log and leaves state management, drift detection, and OPA policy evaluation to the dedicated CI/CD pipeline.

<p class="small mb-4"><a href="https://ecommerce-api.datafortress.cloud/r/brieftechnews/grYC4mZQxG6f3-yLs0r8wA/djF8d2VifDIwMjYtMTAtMzAtZGV2b3BzfGRib3MtYmVuY2htYXJrcy0xMDAwMDAwLWR1cmFibGUtd29ya2Zsb3dzLXBlci1zZWNvbmQtb24tcG9zdGdyZXN8fGh0dHBzOi8vd3d3LmRib3MuZGV2L2Jsb2cvb25lLW1pbGxpb24td29ya2Zsb3dzP3V0bV9zb3VyY2U9YnJpZWYtdGVjaC1uZXdzLmNvbQ" target="_blank" rel="noopener noreferrer">Source: dbos.dev ↗</a></p>

Building durable, distributed execution engines usually requires dedicated coordination systems like Temporal or specialized event buses. [DBOS demonstrated that vanilla PostgreSQL can run over 1,000,000 workflows per second](https://ecommerce-api.datafortress.cloud/r/brieftechnews/grYC4mZQxG6f3-yLs0r8wA/djF8d2VifDIwMjYtMTAtMzAtZGV2b3BzfGRib3MtYmVuY2htYXJrcy0xMDAwMDAwLWR1cmFibGUtd29ya2Zsb3dzLXBlci1zZWNvbmQtb24tcG9zdGdyZXN8fGh0dHBzOi8vd3d3LmRib3MuZGV2L2Jsb2cvb25lLW1pbGxpb24td29ya2Zsb3dzP3V0bV9zb3VyY2U9YnJpZWYtdGVjaC1uZXdzLmNvbQ) by horizontal sharding across 50 `db.m7i.4xlarge` AWS RDS instances (16 vCPUs, 64 GB RAM each).

The ingestion and execution tier ran 48 concurrent workers per shard, handling 20,000 workflow operations per second per database node with PgDog managing connection pooling. The primary bottleneck encountered was a cascading contention loop: whenever an individual Postgres node suffered a momentary I/O hiccup, worker processes backed up, enqueued redundant dequeue transactions, and triggered massive row-level lock contention on the workflow table. 

Engineers stabilized the system by enforcing Postgres advisory locks to throttle concurrent dequeue routines. With connection limits strictly gated, throughput scaled linearly from 20,000 writes on a single instance to a flat 1,000,000 durable executions across the fleet.

<p class="small mb-4"><a href="https://ecommerce-api.datafortress.cloud/r/brieftechnews/ErPPUpxubs46aFSF76ys_A/djF8d2VifDIwMjYtMTAtMzAtZGV2b3BzfHRoZS1yZXNpZHVhbC1yaXNrcy1pbi1naXRodWItYWN0aW9ucy1wd24tcmVxdWVzdHN8fGh0dHBzOi8vd3d3Lndpei5pby9ibG9nL2dpdGh1Yi1hY3Rpb25zLXNlY3VyaXR5LXB3bi1yZXF1ZXN0LXJlY2tvbmluZz91dG1fc291cmNlPWJyaWVmLXRlY2gtbmV3cy5jb20" target="_blank" rel="noopener noreferrer">Source: wiz.io ↗</a></p>

Wiz published an analysis detailing the state of [pull_request_target vulnerabilities](https://ecommerce-api.datafortress.cloud/r/brieftechnews/ErPPUpxubs46aFSF76ys_A/djF8d2VifDIwMjYtMTAtMzAtZGV2b3BzfHRoZS1yZXNpZHVhbC1yaXNrcy1pbi1naXRodWItYWN0aW9ucy1wd24tcmVxdWVzdHN8fGh0dHBzOi8vd3d3Lndpei5pby9ibG9nL2dpdGh1Yi1hY3Rpb25zLXNlY3VyaXR5LXB3bi1yZXF1ZXN0LXJlY2tvbmluZz91dG1fc291cmNlPWJyaWVmLXRlY2gtbmV3cy5jb20) following GitHub’s platform hardening rollout. GitHub has addressed several insecure defaults: `actions/checkout@v7` blocks checking out untrusted fork heads by default, token cache controls are now read-only, and safety patches were back-ported to checkout tags `v2` through `v6`. On December 2, GitHub will enforce a default policy blocking `pull_request_target` usage on public repositories entirely.

However, dangerous escape hatches remain:
* **Immutable Commit Pinning:** Teams that pin actions to full commit SHAs dating before the July 2026 backport release do not receive the patched checkout behavior.
* **Alternative Triggers:** Attackers target pipelines driven by `issue_comment` or `workflow_run`, which retain write privileges and access to repo secrets without the restrictions placed on `pull_request_target`.
* **Private Repositories:** The upcoming December 2 block only affects public repositories. Internal corporate organizations remain exposed to internal lateral movement via forked repos.

Auditing CI configurations for manual git checkouts or downstream evaluations of untrusted expressions like `${{ github.event.comment.body }}` remains mandatory.
