<p class="small mb-4"><a href="https://ecommerce-api.datafortress.cloud/r/brieftechnews/QN-2bTSlTdwwPiBHZnvExw/djF8d2VifDIwMjYtMTAtMTUtaXR8Zml4aW5nLWFuLWlkbGUtMzItbXMtdGFpbC1sYXRlbmN5LXNwaWtlLWluLWNsaWNraG91c2V8fGh0dHBzOi8vY2xpY2tob3VzZS5jb20vYmxvZy9jaGFzaW5nLTMybXMtdGFpbC1sYXRlbmN5LWNsaWNraG91c2U_dXRtX3NvdXJjZT1icmllZi10ZWNoLW5ld3MuY29t" target="_blank" rel="noopener noreferrer">Source: clickhouse.com ↗</a></p>

ClickHouse published a deep dive into an edge case where simple native TCP `SELECT` queries across high-latency connections [doubled their expected round-trip time](https://ecommerce-api.datafortress.cloud/r/brieftechnews/QN-2bTSlTdwwPiBHZnvExw/djF8d2VifDIwMjYtMTAtMTUtaXR8Zml4aW5nLWFuLWlkbGUtMzItbXMtdGFpbC1sYXRlbmN5LXNwaWtlLWluLWNsaWNraG91c2V8fGh0dHBzOi8vY2xpY2tob3VzZS5jb20vYmxvZy9jaGFzaW5nLTMybXMtdGFpbC1sYXRlbmN5LWNsaWNraG91c2U_dXRtX3NvdXJjZT1icmllZi10ZWNoLW5ld3MuY29t), jumping from ~32 ms to ~64 ms after an idle period. 

The culprit was an interaction between the OS TCP stack and database protocol framing. During idle periods, the kernel resets the TCP congestion window (`cwnd`) down to its initial size. When a query ran, ClickHouse's native protocol emitted query data followed by a stream of unbatched trailing metadata frames (`ProfileEvents`, `Progress`, `Logs`) and an `EndOfStream` packet. Even with `TCP_NODELAY` enabled, this cluster of small metadata packets instantly blew through the constricted `cwnd`. The connection had to pause and wait an entire extra RTT for an ACK before flushing the final bytes. ClickHouse eliminated the latency penalty by batching metadata packets at the application layer before handing them to the socket.

```
Idle Connection -> cwnd resets to initial window (e.g., 10 segments)
Query Response  -> Data + Unbatched Metadata (Progress, Logs, EndOfStream)
Result          -> Exceeds cwnd -> Stalls pipeline -> +1 RTT (32 ms penalty)
Fix             -> Application-layer frame batching -> Fits within initial cwnd
```

The Ultra Ethernet Consortium released the [UEC 1.1 specification](https://ecommerce-api.datafortress.cloud/r/brieftechnews/Vor6zhAQsXbfODeVN9Kjaw/djF8d2VifDIwMjYtMTAtMTUtaXR8dWVjLTExLWRyb3BzLXBhY2tldC1vdmVyaGVhZC1mb3ItZ3B1LWZhYnJpY3N8fGh0dHBzOi8vd3d3Lm5ldHdvcmt3b3JsZC5jb20vYXJ0aWNsZS80MjM1MzQwL3VsdHJhLWV0aGVybmV0LTEtMS1leHRlbmRzLXRoZS1zcGVjaWZpY2F0aW9uLXRvLXNjYWxlLXVwLW5ldHdvcmtzLWFuZC1hZGRzLXByb2dyYW1tYWJsZS1jb25nZXN0aW9uLWNvbnRyb2wuaHRtbD91dG1fc291cmNlPWJyaWVmLXRlY2gtbmV3cy5jb20), targeting the scale-up networking fabrics that tie AI accelerator clusters together. 

The update tackles hardware-level bottlenecks:
- **Unified Forwarding Header:** Strips down the 66-byte framing overhead imposed by standard IPv4/UDP encapsulation for intra-rack traffic.
- **Programmable Congestion Management (PCM):** Allows custom telemetry and pacing algorithms to preempt tail latency spikes during heavy collective operations.
- **In-Network Collectives (INC):** Implements hardware-based aggregation directly on switches to accelerate distributed model reduction steps.
