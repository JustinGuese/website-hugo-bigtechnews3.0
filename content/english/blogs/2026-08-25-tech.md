[Port's deep dive into Uber's AI Software Factory](https://ecommerce-api.datafortress.cloud/r/brieftechnews/II-LYbOJCpOa4un53m2onQ/djF8d2VifDIwMjYtMDgtMjUtdGVjaHx1YmVycy1zb2Z0d2FyZS1mYWN0b3J5LTcwLW9mLXBycy1hcmUtYWdlbnRzLW5vd3x8aHR0cHM6Ly9uZXdzbGV0dGVyLnBvcnQuaW8vcC9ob3ctdWJlci1idWlsdC1hLXNvZnR3YXJlLWZhY3Rvcnk_dXRtX3NvdXJjZT1icmllZi10ZWNoLW5ld3MuY29t) is the most concrete reference architecture for agentic coding at org scale that has been published. The numbers are the headline: more than 70% of pull requests at Uber are now written by agents, and code shipped per engineer has doubled in a year. The plumbing underneath is six pieces — a context graph with 40M entries across 150 node and edge types that replaces 20 to 30 source systems, an MCP gateway, an LLM gateway, compute, governance, and workflow orchestration on top.

The MCP gateway is the load-bearing wall. It mediates which tools and resources an agent can see, scopes permissions per task, and is the place where the org's policy actually gets enforced. If you are trying to figure out what an internal agent platform is supposed to look like when you have a few thousand engineers, this is the blueprint. The lesson the author keeps coming back to: platform infrastructure has to exist before agent workflows do, not after.

<p class="small mb-4"><a href="https://ecommerce-api.datafortress.cloud/r/brieftechnews/FgQlrqouzy_ViztSYInoPg/djF8d2VifDIwMjYtMDgtMjUtdGVjaHxzb2xpZC1zdGF0ZS10cmFuc2Zvcm1lcnMtdGhlLWdyaWQtcGllY2UtYWktd2FzLW1pc3Npbmd8fGh0dHBzOi8vYXJzdGVjaG5pY2EuY29tL2dhZGdldHMvMjAyNi8wOC9lbmVyZ3ktaHVuZ3J5LWFpLWRhdGEtY2VudGVycy1zcHVyLW5ldy1wb3dlci10cmFuc2Zvcm1lci10ZWNobm9sb2d5Lz91dG1fc291cmNlPWJyaWVmLXRlY2gtbmV3cy5jb20" target="_blank" rel="noopener noreferrer">Source: arstechnica.com ↗</a></p>

The AI data center boom is now pulling the physical electrical stack behind it. [Ars Technica reports](https://ecommerce-api.datafortress.cloud/r/brieftechnews/FgQlrqouzy_ViztSYInoPg/djF8d2VifDIwMjYtMDgtMjUtdGVjaHxzb2xpZC1zdGF0ZS10cmFuc2Zvcm1lcnMtdGhlLWdyaWQtcGllY2UtYWktd2FzLW1pc3Npbmd8fGh0dHBzOi8vYXJzdGVjaG5pY2EuY29tL2dhZGdldHMvMjAyNi8wOC9lbmVyZ3ktaHVuZ3J5LWFpLWRhdGEtY2VudGVycy1zcHVyLW5ldy1wb3dlci10cmFuc2Zvcm1lci10ZWNobm9sb2d5Lz91dG1fc291cmNlPWJyaWVmLXRlY2gtbmV3cy5jb20) that solid-state power transformers, long a quiet R&D project, are getting serious investment because they slot directly into hyperscaler buildouts. They use high-frequency semiconductor switching, get manufactured from silicon carbide, and do AC-to-DC conversion in one box where the old stack needed separate transformer and rectifier stages.

For an SRE or a data center engineer the relevant differences are size, weight, and modularity. They are physically smaller and lighter than conventional transformers, and the modular design means a failed module gets swapped instead of a transformer getting pulled. The conversion from grid AC to the DC rails the servers actually want happens in a single device, which changes the upstream design assumptions for new builds.

[Vedansh's piece on context engineering](https://ecommerce-api.datafortress.cloud/r/brieftechnews/kgX6KLHZ0pWIUjKQjJwWzw/djF8d2VifDIwMjYtMDgtMjUtdGVjaHxjb250ZXh0LWVuZ2luZWVyaW5nLWlzLWp1c3Qtc3RhdGUtbWFjaGluZS1kZXNpZ258fGh0dHBzOi8vd3d3LnZlZGFuc2hoLmNvbS9ibG9nL2NvbnRleHQtZW5naW5lZXJpbmc_dXRtX3NvdXJjZT1icmllZi10ZWNoLW5ld3MuY29t) reframes the agent stack with one useful line: the context window is the whole state machine. Every piece of a harness either adds information to the model's context, gates what gets in, or validates what comes out. The trap is thinking in terms of which components to add — the real question is what is worth keeping when the context is finite.

If you have ever tried to bolt a RAG layer onto a chat agent and watched it get slower and weirder, this is the framing that explains why. The harness is not an assembly of features, it is a state machine with a fixed budget, and the discipline is choosing what to evict.

<p class="small mb-4"><a href="https://ecommerce-api.datafortress.cloud/r/brieftechnews/2Tz5ZPa48Ho6PM8NoEi7Wg/djF8d2VifDIwMjYtMDgtMjUtdGVjaHxzcWxpdGUtYXMtYW4tZXhlY3V0YWJsZS1mb3JtYXR8fGh0dHBzOi8vZnpha2FyaWEuY29tLzIwMjYvMDgvMjMveW91ci1leGVjdXRhYmxlLWlzLWEtc3FsaXRlLWRhdGFiYXNlP3V0bV9zb3VyY2U9YnJpZWYtdGVjaC1uZXdzLmNvbQ" target="_blank" rel="noopener noreferrer">Source: fzakaria.com ↗</a></p>

[Farid Zakaria's prototype](https://ecommerce-api.datafortress.cloud/r/brieftechnews/2Tz5ZPa48Ho6PM8NoEi7Wg/djF8d2VifDIwMjYtMDgtMjUtdGVjaHxzcWxpdGUtYXMtYW4tZXhlY3V0YWJsZS1mb3JtYXR8fGh0dHBzOi8vZnpha2FyaWEuY29tLzIwMjYvMDgvMjMveW91ci1leGVjdXRhYmxlLWlzLWEtc3FsaXRlLWRhdGFiYXNlP3V0bV9zb3VyY2U9YnJpZWYtdGVjaC1uZXdzLmNvbQ) replaces ELF with SELF — a Structured Executable & Linkable Format whose on-disk representation is a SQLite database you can `chmod +x` and run. The post maps ELF internals onto database primitives: string interning instead of strtab, indexes instead of `.gnu.hash`, schema tables instead of section headers, b-tree pages instead of segment layouts, foreign keys instead of relocations. There is a working `sqlelf` tool for SQL-based ELF exploration, and the code is on GitHub.

If this proves out, executables become queryable, mutable, and dramatically more inspectable — and a lot of the awkward tooling that grew up around `readelf`, `objdump`, and `nm` gets replaced by SQL.

<p class="small mb-4"><a href="https://ecommerce-api.datafortress.cloud/r/brieftechnews/AyI_WByatROJJigKe3t7uA/djF8d2VifDIwMjYtMDgtMjUtdGVjaHxzdGFybGluay13YW50cy10by1iZS1hLWNlbGwtY2Fycmllci1mcm9tLXNwYWNlfHxodHRwczovL3BvdHNhbmRwYW5zYnljY2cuY29tLzIwMjYvMDgvMjQvc3RhcmxpbmtzLWludGVyZXN0aW5nLWFwcHJvYWNoLXRvLWNlbGx1bGFyLz91dG1fc291cmNlPWJyaWVmLXRlY2gtbmV3cy5jb20" target="_blank" rel="noopener noreferrer">Source: potsandpansbyccg.com ↗</a></p>

On SpaceX's first earnings call, [Starlink laid out a plan to enter terrestrial cellular](https://ecommerce-api.datafortress.cloud/r/brieftechnews/AyI_WByatROJJigKe3t7uA/djF8d2VifDIwMjYtMDgtMjUtdGVjaHxzdGFybGluay13YW50cy10by1iZS1hLWNlbGwtY2Fycmllci1mcm9tLXNwYWNlfHxodHRwczovL3BvdHNhbmRwYW5zYnljY2cuY29tLzIwMjYvMDgvMjQvc3RhcmxpbmtzLWludGVyZXN0aW5nLWFwcHJvYWNoLXRvLWNlbGx1bGFyLz91dG1fc291cmNlPWJyaWVmLXRlY2gtbmV3cy5jb20) by deploying cell sites with satellite backhaul, riding on next-gen V3 satellites and the existing constellation. The obstacles are concrete: the US cellular market is already competitive, Starlink only acquired 65 MHz from EchoStar against an 800 MHz FCC auction mandate, and feeding hundreds of thousands of cell sites from a constellation currently sitting at roughly 15,000 approved satellites is a real bandwidth problem. The requests to grow the constellation to 100,000 are still pending.

The author's read: the US is the harder market, and developing markets like Nigeria are a more realistic first target. The plan's feasibility hinges on spectrum acquisition, V3 capacity, and how fast the constellation actually scales.
