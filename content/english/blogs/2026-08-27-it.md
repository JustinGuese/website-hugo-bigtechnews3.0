Nvidia just posted $96.2 billion in quarterly revenue—more than double last year's number, with data center revenue alone hitting $89 billion. The company's Q3 forecast implies an 89% year-over-year revenue increase. If you're not paying attention to AI infrastructure demand, you should be: CFO Colette Kress noted supply is constrained at roughly 70% of what's being asked for. ## Nvidia Doubles Revenue Again as AI Compute Demand Outpaces Supply

The headline number is $96.22 billion for Q2, crushing the $92.27 billion analyst consensus. Net income came in at $59.69 billion versus $26.42 billion last year—$2.46 per share against $1.08. The company guided Q3 to approximately $108 billion, implying sustained 89% year-over-year growth through the fiscal year ending January 2028.

The data center segment drove almost all of it at $89 billion. Kress was blunt on the earnings call: supply is running at about 70% of demand, capping what would otherwise be closer to double-digit growth. For teams procuring GPU capacity or architecting AI workloads, that supply constraint isn't theoretical—it's a direct factor in lead times, pricing, and capacity planning. The compute shortage is still structural.

## Salesforce Embeds Live CRM Data Directly Inside Claude

Salesforce and Anthropic launched [Claudeforce](https://venturebeat.com/orchestration/salesforce-just-put-its-entire-crm-inside-claude-and-says-youll-never-need-its-app-again), bringing live CRM data and workflows directly into Claude without the traditional API dance. The initial release ships with 37 sales skills covering pipeline analysis, account research, and deal reviews.

This is different from RAG or chat interfaces over CRM exports. Claudeforce accesses Salesforce's live data model, meaning the AI can work with current pipeline state rather than snapshots. For engineers building AI-augmented sales tools or integrating LLMs with enterprise data, this pattern—tight coupling of an LLM to a live data backend with structured skills—represents a shift from "ask the AI questions" to "let the AI work inside your systems." It's early and Salesforce-specific, but it's a concrete example of where AI assistant UX is heading.

## CISA Orders Federal Agencies to Patch Actively Exploited Oracle Flaw by End of Today

CISA added [CVE-2026-21962](https://itnerd.blog/2026/08/25/the-cisa-orders-federal-agencies-to-patch-actively-exploited-oracle-flaw-by-august-27/) to its Known Exploited Vulnerabilities catalog, setting a remediation deadline of today, August 27. The vulnerability—affecting Oracle HTTP Server and the Oracle WebLogic Server Proxy Plug-in—carries a CVSS score of 10.0 and can be exploited remotely without authentication to access, modify, or delete critical data.

Here's the kicker: Oracle patched this in January 2026. Public exploit code emerged in March. CISA's KEV addition came 216 days after the patch was available. Roughly 79,000 Oracle HTTP Server instances are exposed on Shodan. Agencies that delayed now face BOD 26-04 forensic triage requirements alongside the three-day remediation window. If you're running Oracle HTTP Server or WebLogic in any infrastructure you manage, the question isn't whether to patch—it's whether you can prove you patched before March.

## AI Is Rewriting the Rules of Competitive Strategy

Benedict Evans's [Substack piece on strategy in the age of AI](https://platforms.substack.com/p/strategy-in-the-age-of-ai-eight-points) argues that AI changes the fundamental rules of competition, not merely the efficiency of operations. As intelligence becomes abundant within individual modules, advantage shifts to those who can connect activities and learn across boundaries.

The key theses: the unit of value may need redefining; translating across incompatible systems becomes a competitive moat; and vertical integration may return—not through physical assets but through ownership of feedback loops. Evans's warning is sharp: operational excellence can become strategically destructive when the underlying economic value of the work itself is shifting. For engineers and technical leaders, this isn't just business strategy jargon. It has concrete implications for which systems you build, which data you own, and which integrations you prioritize.

## MCP's 2026 Revision Makes It a First-Class HTTP Workload

The [July 2026 breaking revision to the Model Context Protocol](https://pub.towardsai.net/mcp-2-0-what-changed-what-remained-and-how-it-impacts-practitioners-8f553e62448c) doesn't create an "MCP v2"—it reframes MCP as an HTTP ecosystem profile. The protocol removes handshakes and protocol sessions, making state live in requests and server-side data models instead. Load-balanced deployment becomes straightforward.

The revision also standardizes an authorization profile, tool-risk annotations, and embedded interfaces. For teams building AI agents or integrating multiple tools with LLM backends, this matters: MCP is now easier to operate as a standard HTTP service rather than a bespoke protocol requiring special handling. If you've been waiting for MCP to stabilize before betting on it for production systems, the architectural direction is clearer.

## Vercel Releases Run SDK for Sandboxed Agent Code Execution

Vercel shipped the [Run SDK](https://vercel.com/blog/introducing-run) (`pnpm add run`) for executing untrusted JavaScript and TypeScript in sandboxed environments using QuickJS within worker threads. The sandbox has no direct access to Node.js or the network. Applications expose operations through `hostFunctions`—regular functions callable as globals inside the sandbox, with calls crossing the boundary via serialization.

This powers code mode in Vercel's AI SDK, enabling agents to generate programs that describe both API calls and the connecting logic. For engineers building agentic systems, this is a concrete pattern for safely executing LLM-generated code against real applications without exposing secrets or system resources. If you're building anything where an agent needs to write and run code, this approach—narrow host APIs plus serialization boundary—is worth studying.

## AWS Acquires DuckLabs, Keeps DuckDB Open Source

Amazon signed a [definitive agreement to acquire DuckLabs](https://aws.amazon.com/blogs/big-data/aws-and-ducklabs-building-the-future-of-analytics-together/), the Amsterdam-based company behind DuckDB. Founders Hannes Mühleisen and Mark Raasveldt will continue leading the open-source project under the independent DuckDB Foundation and MIT license.

DuckDB—created at CWI, the Dutch research institute behind Python—specializes in fast vectorized queries against up to 1TB of data, running in-process. Engineers using DuckDB for analytical workloads should expect tighter AWS integration (Redshift Magics, Athena federated queries, and Glue come to mind) while the core remains open. This is the second major open-source database project to land at a hyperscaler this year; the playbook is consistent.

## RPM's "Pristine Sources" Philosophy Remains the Backbone of Enterprise Linux

The [history of RPM](https://bubble.ro/2026/08/25/the-history-of-rpm-how-a-pristine-sources-rule-became-the-backbone-of-enterprise-linux/) traces its defining innovation to the "Pristine Sources" build philosophy: unmodified upstream tarballs plus separate patch files and spec-file instructions, rather than directly modified source trees. Written in 1997 by Erik Troan and Marc Ewing at Red Hat, this architecture enabled distributions to rebase onto new upstream versions by re-running builds—no hand-merging forks required.

The dependency resolver lived outside RPM for two decades before libsolv replaced it. For engineers maintaining package specs, understanding this philosophy explains why RPM's design prioritizes rebasing and auditable diffs over direct source modification. It's why `rpm -ba` with a clean spec file still works the same way it did in 1998.
