<p class="small mb-4"><a href="https://ecommerce-api.datafortress.cloud/r/brieftechnews/JYZALG6ldr6L4I5zfG-dtQ/djF8d2VifDIwMjYtMTAtMTYtY3J5cHRvfHJhcGlkYmxvY2tzLWRlY291cGxpbmctZXZtLWV4ZWN1dGlvbi1wcm9vZnMtZnJvbS1zdGF0ZS1yb290c3x8aHR0cHM6Ly9ldGhyZXNlYXIuY2gvdC9yYXBpZGJsb2Nrcy13aXRoLXNwbGl0LXByb29mcy1leGVjdXRpb24tcHJvb2ZzLXRoYXQtb3V0bGl2ZS10aGVpci1zdGF0ZS8yNjE1Nz91dG1fc291cmNlPWJyaWVmLXRlY2gtbmV3cy5jb20" target="_blank" rel="noopener noreferrer">Source: ethresear.ch ↗</a></p>

Engineers designing rollup sequencing and validity pipelines have a new architecture to review. A proposal published on [ethresear.ch details "Rapidblocks with split proofs"](https://ecommerce-api.datafortress.cloud/r/brieftechnews/JYZALG6ldr6L4I5zfG-dtQ/djF8d2VifDIwMjYtMTAtMTYtY3J5cHRvfHJhcGlkYmxvY2tzLWRlY291cGxpbmctZXZtLWV4ZWN1dGlvbi1wcm9vZnMtZnJvbS1zdGF0ZS1yb290c3x8aHR0cHM6Ly9ldGhyZXNlYXIuY2gvdC9yYXBpZGJsb2Nrcy13aXRoLXNwbGl0LXByb29mcy1leGVjdXRpb24tcHJvb2ZzLXRoYXQtb3V0bGl2ZS10aGVpci1zdGF0ZS8yNjE1Nz91dG1fc291cmNlPWJyaWVmLXRlY2gtbmV3cy5jb20), a framework that enables execution proofs to remain valid across different slots even if the global state changes.

Normally, validity proofs bind a specific pre-state root to a post-state root. If an earlier transaction modifies any unrelated slot in the state trie, the pre-state root changes, invalidating a generated proof and requiring expensive re-execution. Rapidblocks breaks a monolithic block proof into three discrete components:

* $\Pi_T$: Verifies pure transaction execution logic strictly against the specific values read by the transaction, without binding to an overall state root.
* $\Pi_{in}$: A Merkle inclusion proof verifying that the read values existed in the pre-state root.
* $\Pi_{out}$: A Merkle proof verifying that written state modifications correctly update into the post-state root.

By committing directly to input values inside the block header rather than the global state root, $\Pi_T$ stays valid across slots as long as nobody touches the accessed keys. This lets validators advance block consensus asynchronously without waiting for complete state-root finalization. However, production readiness is still far off: blocks require proving times under 2.5 seconds, witness sizing for Merkle-Patricia tries remains unsolved, and formal verification has so far only passed bounded model checking on small configurations.

[Chainalysis data indicates AI agents executed over 138 million transactions](https://ecommerce-api.datafortress.cloud/r/brieftechnews/LiEZ1zK6-9TUrEOXvqlcsQ/djF8d2VifDIwMjYtMTAtMTYtY3J5cHRvfGFnZW50aWMtY29tbWVyY2UtZ2VuZXJhdGVzLTEzOC1taWxsaW9uLW1pY3JvLXRyYW5zYWN0aW9uc3x8aHR0cHM6Ly9kZWNyeXB0LmNvLzM4MDk4OS9haS1hZ2VudHMtMTM4LW1pbGxpb24tY3J5cHRvLXBheW1lbnRzLW9uZS15ZWFyP3V0bV9zb3VyY2U9YnJpZWYtdGVjaC1uZXdzLmNvbQ) on Coinbase's Base Layer 2 via the x402 protocol between mid-2025 and Q3 2026. The transaction size distribution explains why these workloads avoid traditional payment rails: more than 87% of all recorded transfers fell between $0.01 and $0.10. Credit card interchange structures make sub-dime payments cost-prohibitive, leaving low-fee stablecoin rails as the only practical settlement layer for automated API calls and per-query inference.

The transaction demographic shows geographic specialization:
* Wallets associated with US entities generated 88.1% of all AI inference spend.
* Chinese wallets accounted for only 0.1% of inference payments, but made up the majority of machine-to-machine spending on automated smart-contract auditing and code-analysis services.

TRM Labs added a note of caution, warning that an undetermined share of the 138 million transactions likely stems from looping cron scripts and wash-volume self-dealing rather than strictly autonomous LLM-driven agents.
